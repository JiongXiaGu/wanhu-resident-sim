# 居民头像系统与美术资源规范 V1

## 目标

本规范服务 Web 玩法原型，当前验证：

1. 同一个居民的视觉身份是否稳定；
2. 连续查看几十个居民时是否容易区分；
3. 性别、年龄与家庭生活条件能否自然体现在头像上；
4. 当前验证过的外观语义未来是否能继续迁移到 Unity。

Web 当前使用分层 SVG 只是验证手段，不代表未来 Unity 必须使用 SVG，也不在这里定义正式 Runtime / Save 结构。

本轮正式美术方向与资产清单见：

```text
Documentation/Portrait Art Kit V1.md
```

## 核心原则：迁移语义，不迁移 Web 渲染代码

当前稳定层仍是 `AppearanceDNA`：

```text
faceId
hairId
browId
facialHairId
headwearId
outfitId
skinPaletteId
hairPaletteId
clothingPaletteId
```

Web：

```text
AppearanceDNA
↓
Gender / LifeStage / Household Appearance Resolver
↓
Face Compatibility + Silhouette Diversity
↓
PortraitRig
↓
Layer Renderer
↓
分层 SVG
```

未来 Unity：

```text
AppearanceDNA
↓
Unity Appearance Resolver
├─ 2D Portrait Sprite / Atlas
└─ 3D Mesh / Hair / Material / Outfit
```

同一个 Stable ID 可以在不同表现层映射到不同资源。`appearance.hair.female-braid-01` 首先代表一种经过审核的外观语义，而不是某一张 SVG 文件。

## 风格方向

正式方向固定为：

```text
扁平古风 + 轻纸片拼贴感
```

阅读层次：

```text
脸和发型先认人
衣领和肩线看财富
少量配饰提气质
年龄 Overlay 补人生阶段
```

统一要求低饱和、克制、温润。富裕通过层次、完整度和协调感表达，而不是更鲜艳；贫寒通过更素、更简单表达，而不是更脏。

## 4:5 美术母版与 1:1 Safe Area

正式源文件统一为：

```text
1024 × 1280
4:5
透明背景
```

其中定义居中的 1:1 Safe Area：

```text
x = 0 .. 1024
y = 128 .. 1152
size = 1024 × 1024
```

Web 使用等价归一化坐标：

```text
Master: 120 × 150
Safe Area: x=0..120, y=15..135
```

居民列表和大多数 UI 仍按 1:1 圆角方形裁切。

必须位于 Safe Area 内：

- 脸；
- 主要五官；
- 主发型轮廓；
- 主要衣领；
- 胡须主体；
- 主要肩线。

允许少量突破：

- 发髻顶端；
- 发簪；
- 长发 / 辫子末端；
- 少量肩线与上胸延伸。

突破部分不得承载人物识别所必需的信息。

## 胸像构图

- 近正面；
- 头部约占 Safe Area 高度 60%～65%；
- 肩宽约 2 个头宽；
- 露出头部、颈部、肩膀和少量上胸；
- 优先保证 48×48 / 64×64 / 96×96 下仍然可辨认。

## PortraitRig

每一个 `appearance.face.*` 必须具有 `faceFamily + rig`。

Face Rig：

```text
centerX
 topY
 hairlineY
 browY
 eyeY
 noseY
 mouthY
 chinY
 faceWidth
 jawWidth
 earY
 neckTopY
 shoulderY
```

附属层只依赖 Rig：

```text
Back Hair   → topY + hairlineY + faceWidth + shoulderY
Front Hair  → topY + hairlineY + faceWidth
Brow        → browY + faceWidth
FacialHair  → mouthY + chinY + jawWidth
Headwear    → topY + faceWidth
Neck        → neckTopY
Outfit      → shoulderY
Age Overlay → eyeY + mouthY + jawWidth
```

因此新增一个脸型时只需要校准一套 Face Rig，不重新维护“某张脸 + 某个胡须”的 Offset 表。

### Rig 硬规则

编译与头像实验室检查：

- `topY < hairlineY < browY < eyeY`；
- `eyeY < noseY < mouthY < chinY`；
- 下巴、脖颈和肩线顺序有效；
- `jawWidth <= faceWidth`；
- 脸和主要肩线保持在 1:1 Safe Area 内；
- 女性不会生成胡须；
- 未成年不会生成不允许的胡须组合。

硬规则失败属于装配错误。

## 美术分层

统一层级：

```text
Background
Back Hair
Body / Outfit
Neck
Face Base
Brow / Face Detail
Front Hair
Facial Hair
Headwear / Accessory
Age Overlay
```

### Face Base

Face Base 负责主要脸型与核心五官风格，不把左右眼、鼻子、嘴、耳朵继续拆成完全自由的随机模块。

小尺寸头像里，脸型、发型、胡须、头饰与衣领轮廓比微小五官差异更重要。

### Back Hair

女性长发、辫子、低髻等必须真正改变人物外轮廓，并可延伸到脸两侧、肩膀外侧和上胸区域。

### Front Hair

只负责发际线、额前结构和少量脸侧发束，不承担整个长发体积。

### Outfit

Outfit 按生活条件而不是职业拆层级：

```text
poor         贫寒
plain        普通
comfortable  殷实
wealthy      富裕
```

职业名称可以显示在居民信息中，但不进入服装候选池。

## Compatibility Resolver

物理位置正确以后，仍可能出现审美上不理想的组合。部件可以声明：

```text
preferredFaceFamilies
avoidFaceFamilies
```

当前权重：

```text
preferred → × 1.35
avoid     → × 0.30
```

这是软偏好，不是硬禁止。

当前 Face Family：

```text
oval
round
long
square
broad
```

## 资源 Fit 与 silhouetteType

当前内容字段直接承担 Fit 语义：

```text
genders             = genderFit
lifeStages           = ageFit
wealthTiers          = wealthFit
presentationStyles   = presentationFit
weight               = 基础随机权重
```

不再增加一套重复字段。

Hair 与 Outfit 额外要求：

```text
silhouetteType
```

它描述小尺寸下真正可读的轮廓家族，例如：

```text
female-long-straight
female-braid-long
female-bun-low
male-tied-high
poor-single-collar
wealthy-layered
```

## Silhouette Diversity

同屏随机不能只追求 AppearanceDNA 字符串不同，还要避免轮廓连续重复。

ResidentAppearanceCompiler 会按性别维护最近的 Hair silhouette 历史：

- 最近刚出现：强降权；
- 数人之前出现：中度降权；
- 更久之前出现：轻度降权；
- 最近未出现：略微增权。

Portrait Lab 在人工美术验证时进一步优先从最近 4 个未出现过的轮廓中挑选。

目标不是全城永不重复，而是避免玩家连续看到一串相同头型。

## Headwear / Hair 遮挡

每个 Headwear 必须声明：

```text
hairVisibility = full | back-only | hidden
```

含义：

- `full`：前后头发都保留，如无头饰、发簪、宽檐笠；
- `back-only`：保留后发轮廓、隐藏前发，适合布巾、小帽、小头巾；
- `hidden`：预留给未来完全替换顶部发型的头饰。

正式 Unity 美术继续沿用此遮挡语义，具体 Sprite Mask / Mesh / Material 方案届时再定。

## 调色板

### Skin

四档暖肤：

```text
浅暖
中浅暖
偏深暖
较深褐
```

### Hair

```text
乌黑
深棕黑
棕黑
深褐
灰黑
花白
银灰
```

灰发由年龄提高出现概率，不要求所有老人都白发。

### Clothing

主色集中在：

```text
麻白
土黄
灰褐 / 灰棕
深褐
青灰
靛青
墨绿
藕灰
暗红
```

同一服装未来不应为了颜色重复导出多张资源。Unity 推荐使用区域 Mask + Material 映射 `clothingPaletteId`。

## 年龄表现

年龄变化优先保持核心身份稳定：

```text
Face Base        尽量保持
Brow             通常保持
Hair Family      可在同家族内变化
Hair Palette     随年龄变化概率提高
Age Overlay      中年 / 老年增加
Facial Hair      按年龄和性别变化
```

目标是让玩家感觉“同一个人老了”，而不是每个阶段重新随机一张脸。

## 家庭财富与讲究程度

头像主要读取：

```text
Gender
LifeStage
Household.WealthTier
Household.PresentationStyle
```

`PresentationStyle`：

```text
practical  实用
tidy       整洁
refined    讲究
```

这允许：

- 富裕但低调；
- 普通但很整洁；
- 殷实且讲究。

同一 Household 共享生活条件语义，但居民的脸、发型、配色和附件仍保持大量差异。

## Web 头像实验室

入口：

```text
/?view=portraits
```

当前一次生成 64 个样本，并提供：

- 性别 / 财富 / 讲究程度 / 年龄 / Face Family 筛选；
- 4:5 美术母版；
- 1:1 实际裁切；
- PortraitRig + Safe Area；
- Back Hair / Front Hair 分层开关；
- Brow / Beard / Headwear / Outfit / Age Overlay 开关；
- AppearanceDNA；
- Hair silhouette；
- 相邻轮廓重复计数；
- Rig 硬错误与兼容提醒；
- 换一批随机样本。

前 8 个覆盖样本固定包含女性四档财富、富裕老年女性，以及不同财富男性，便于每次打开直接对比。

## 美术验收标准

1. 默认 64 个头像没有 PortraitRig 硬错误；
2. 方形裁切中脸、主要发型、衣领和胡须不被破坏性裁掉；
3. 女性长发、辫子、盘发在小尺寸下明显改变外轮廓；
4. 女性不再只是“没有胡子的男性脸”；
5. 贫寒 / 普通 / 殷实 / 富裕能通过领口与完整度读出差异；
6. 富裕不靠鲜艳，贫寒不靠污渍；
7. 相邻 Hair silhouette 重复明显减少；
8. Headwear 不与 Front Hair 发生明显穿插；
9. 老人不是简单把头发变白；
10. 职业不直接决定服饰；
11. 部件新增后旧 Stable ID 的语义不随意改变。
