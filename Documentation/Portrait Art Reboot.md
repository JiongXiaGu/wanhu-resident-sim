# Resident Portrait Art Reboot

## 当前决策入口

`/?view=portrait-art-reboot`

这是新的美术方向对比页。正式入口 `/?view=portraits` 保持不变；旧 `portrait-style-study` 和 `portrait-style-bakeoff` 只作为历史比较，不再是本轮新美术的模板。

## 为什么重做

上一轮截图与源码暴露了两个层次的问题：

- 局部：眼部线条细弱、发际线缺乏体积、领口近似折纸标签、老人依赖灰发和细纹。
- 方向：数个命名不同的候选仍使用相近的长脸比例、正面五官、头发外轮廓和梯形衣身。身份主要靠颜色及附加装饰改变，缺少独立的人物设计。

因此不继续修补旧 A–F。新页不引用生产 PortraitRenderer、Face/Hair/Outfit 路径或旧实验路径，也不修改生产 DNA、Frame、RenderPlan、Catalog 或居民快照。

## 三个候选方向

| 方向 | 构造和介质 | 需要确认的问题 |
| --- | --- | --- |
| 绢色人物 | 角色设定式栅格插画、偏侧面、衣料笔触、多级明暗 | 插画完成度与小尺寸简化能否兼得 |
| 市井绘本 | 独立作画的 SVG、脸型与五官偏转、非对称发束、概括色面 | 普通居民的亲和感、清晰度与群体变化空间 |
| 陶彩小像 | 独立 SVG 2.5D 体积绘制、较大头部、较短中庭、圆润轮廓 | 玩偶感是否适合游戏，以及高阶人物的庄重感 |

每组有平民女性、平民男性、老人、贵族女性、高阶男性。老人样本有意覆盖男女，但不是严格同一个人物的跨风格重绘；本页不应被解释为五种 FaceFamily 或同一人的换装。

三组不构成不同身份阶层各用一套画风。选型后普通人与皇室必须回到同一种插画语言。

## 当前素材与边界

目录：`Web/public/portrait-art-reboot/`

- `painted.avif`：960 × 192 五格栅格母板；单幅有效分辨率为 192 × 192。来自本轮生成式角色概念探索，经裁切整理与压缩，包含纸色背景。不是分层母稿，冠顶原始裁切仍需在正式设计中解决。
- `graphic.svg`：1600 × 320，五个独立角色 group。角色轮廓、五官、衣身和冠发分别作画，透明底。
- `clay.svg`：1600 × 320，五个独立角色 group。共享的只是该画风的色彩/光照定义，不引用另一候选或生产几何。透明底。它是 2.5D 图形 Proof，不是已存在的 3D 模型、绑定或离线烘焙管线。

SVG 中每个 group 的横向位置只用于将五幅独立画稿放入素材条；这不是生产 Runtime 的 Anchor / Offset Solver。

这些素材是方向 Proof，不能宣称已经满足量产、模块化、年龄一致性或 Unity 生产就绪。不要把当前小分辨率栅格当成生产源文件。

## 页面评审功能

- 三组 × 五种角色的整体比较。
- 点击任一角色，用原生 dialog 比较同类角色；支持 Escape、关闭按钮和焦点回到触发按钮。
- 48 / 64 / 96 CSS px 的真实尺寸矩阵，各方向、各角色全部覆盖。
- 深浅底色切换。栅格插画保留原画纸底；矢量使用透明背景；不伪称栅格也完成了透明合成。
- 各方向的优点、缺口与量产路径说明。
- 临时候选清单与 JSON 导出。选择只存在页面状态中，不写入 localStorage、居民 Snapshot 或 DNA。

不制作“五个头像重复排列就代表千人多样性”的虚假群体证明。

## GitHub Actions 验收

继续使用既有 Build 和 Resident Visual Review，不使用 Vercel、Preview、Production 或外部图像 CDN。

`capture-portrait-art-reboot.mjs` 是新页专用验收，接在既有居民玩法与正式头像回归检查后面，不能替代原检查。自动覆盖素材解码、方向/角色数量、Runtime 隔离、dialog 交互、焦点恢复、清单导出、45 个真实像素尺寸、深浅底色和 390 px 宽度。

截图编号 80–90：总览、三个方向近景、老人/贵族对照、深色总览、深浅像素矩阵、移动端。桌面截图宽 1560 px，小于现有压缩器 1600 px 上限，因此像素矩阵不会在压缩阶段再次缩放。

Artifact 还提供该次提交的 `reviewed-source.zip`，便于与截图对应地检查完整源码。

`portrait-art-reboot-checks.json` 只表示自动断言结果。**CI PASS 不是美术批准。** 合入 main 前必须下载当前临时分支 Artifact 并实际看图；main 更新后再次确认对应 Actions 和截图。

## 选型后的下一道关

1. 用户选择一个主方向，必要时保留一个对照方向。
2. 将所选方向重绘成统一姿态与构图，补齐儿童和另一性别老人。
3. 先验证一个 Frame 内有辨识度的多个脸型、发型、衣服以及真实 48 px 表现。
4. 再扩到六个固定 Frame，验证同一身份的年龄延续及合理数量居民的重复率。
5. 最后回归 `Documentation/Portrait System.md` 的五 ID、六 Frame、五层 RenderPlan；不引入自动适配器，也不在本仓库设计 Unity ECS / Save。

这里讨论的是生产路径候选，不是已经实现了这些路径。
