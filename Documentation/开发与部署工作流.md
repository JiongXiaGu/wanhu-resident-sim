# 开发与视觉审查工作流

远端只使用 GitHub Actions：Build 与 Resident Visual Review。不依赖 Vercel、Preview、Production。

## 原子批次

最新 main 与项目文档 → tmp-* → 集中改代码、素材和文档 → 一个聚合提交 → 两个 workflow → 下载 Artifact 并看图 → 必要时聚合修正 → 重读 main → 推进已审查提交 → main 重跑和复核。

可以使用 Git Data API create_blob/create_tree/create_commit/update_ref。禁止一文件一提交、空提交刷检查、force 覆盖新 main。合并前若 main 有新工作，先整合再审查。

## Build

`.github/workflows/validate.yml` 安装依赖、构建 Content、上传 generated Artifact 并执行 Web TypeScript/Vite build。generated 不手改；内容变更须同步 Schema、Compiler 与消费者。本仓库不设计 Unity ECS/Blob/正式存档。

## Resident Visual Review

保留以下职责：

| 脚本 | 责任 |
| --- | --- |
| capture-resident-review | 居民生活/历史、故事与婚姻/LifeTag 连续性 |
| capture-portrait-review | 冻结正式 fallback 的六 Frame 与 72 组合契约 |
| capture-avatar-review + audit-packs | Catalog 全组合、头型/头发/图层/兼容、玩家居民保存、真实 UI |
| review-avatar-integration | 入口不遮挡游戏、延迟导入、应用后切对象与原子目标切换 |
| capture-avatar-art-polish | 所有 Frame × Face × Expression 的腮红安全区/真实轮廓和负对照 |
| capture-avatar-foundation | Phase 8A 六框架自由创作、独立保存/刷新/草稿、随机过滤和帽发衣装样板图 |

数据数量从 Catalog 读取，不以四脸/192 或旧总组合数作为永久契约。图板统一使用 audit-packs 的 renderBoards。

## 截图与 Artifact

`avatar/source-commit.txt` 记录精确 SHA；`source-and-contract.zip` 保存该提交的头像源码、治理文档和 workflow。`avatar/` PNG 保留原始尺寸，不参与 legacy 根预览压缩。

当前人工审查重点为桌面美术。按用户最新要求，不再产出 `avatar/11-mobile.png`，不要求移动端人工审查；原 390/320px 溢出 smoke check 可保留但不截图。

Phase 8A 至少实际打开：`avatar/phase8a/studio-female.adult.png`、`studio-female.child.png`、`studio-male.elder.png`、`studio-headwear.png`、`studio-outfits.png`、`bound-resident.png`、六张 `faces-<frame>.png`、`headwear.png`、`outfits.png`、`six-frame-overview.png`。同时查看腮红诊断和 96/64/48px 原尺寸。

自动报告只能证明契约通过。帽身被头发截断、领口断开、脸型别扭、底部出现不明横块时继续修。不得把生成了图板写成看过，也不得把技术 PASS 写成用户接受。

## 自由创作 / 指定对象

自由创作保存到独立 `studio:<frame>` 键，不接触玩家/居民旧键。切换 Frame 仍走草稿确认，晚到的导入不能污染新 Frame。指定居民的年龄/性别来自居民状态，不能从创作控制改写。

继续验证甲乙保存隔离、取消不写、刷新恢复、恢复只删当前键、同对象外部更新冲突、配额失败不假成功。自由创作不重建 App、不改故事和游戏日期。

## 交付

先写已完成范围、main SHA、Build/Resident Visual Review 状态、是否下载人工看图。贴关键桌面真实截图和本轮诊断图，不额外打包全部 Artifact。区分已实现功能、候选美术/用户待验收、未完成范围。阶段文档记录样板实际审查，不自动扩量或迁 Unity。
