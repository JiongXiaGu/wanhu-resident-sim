# 开发与视觉审查工作流

当前远端验收仅使用 GitHub Actions：Build 与 Resident Visual Review。不依赖 Vercel、Preview、Production 或线上临时站点。

## 原子批次

```text
读取最新 main 和项目文档
→ 从该 SHA 创建 tmp-*
→ 集中修改源码、素材、必要文档
→ 一个聚合 commit / 一次 push
→ Build + Resident Visual Review
→ 下载 Artifact、实际查看关键截图
→ 必要时再作一个聚合修正 commit
→ 两类检查与视觉审查通过
→ 重新读取 main SHA，不强制覆盖他人工作
→ 一次推进 main
→ main 再跑检查并下载复核
```

使用 create_blob → create_tree → create_commit → update_ref，或等价本地批量提交。不要一文件一提交、空提交刷新结果，或在审查前推进 main。main 若已变化，重新核对并整合，而不是 force push。

## Build

保留 `.github/workflows/validate.yml`：安装依赖 → npm run build-content → generated Artifact → Web TypeScript/Vite build。

Content、Schemas、Compiler、Coverage 仍服务 Web 原型，不设计 Unity ECS/Blob/正式存档。生成物不手工编辑，逻辑内容变更须同步契约、编译器、Web 消费代码与验证。

## Resident Visual Review

Runner 内启动本地 Vite，Playwright 执行真实交互，上传 resident-visual-review Artifact。

当前保留：

- capture-resident-review：居民生活、人生经历、memoryText、婚姻/家庭与 LifeTag 连续性。
- capture-portrait-review：正式 fallback 的六个 Frame、72 组合及原有合同检查。
- capture-avatar-review + `scripts/avatar-review/audit-packs.mjs`：统一四选项工坊、真实玩家/居民隔离保存、草稿/取消/导入/冲突、真实居民面板显示；素材审查从 Pack Registry 自动读取注册画风，并从各 Pack-owned Catalog 动态计算 Face × Hair × Outfit × Expression 组合数，再用每画风小型 Review Spec 驱动部件导出与图板检查。

用户已要求清理错误实验：不再保留被否定的风格页、整图图库、专属素材和专属测试。删除错误实验不等于删除仍有效的居民玩法或正式 fallback 测试。

## 截图与真实审查

`avatar/` 子目录保留原始 PNG、部件 SVG、manifest 和检查报告，不经过根目录预览缩图。每个 Pack 的素材审查统一放在 `avatar/packs/<pack-id>/`，跨画风对照放在 `avatar/style-comparisons/`。诊断图板必须标明是组合审查，不能冒充玩家界面或固定整图素材。

必须打开：编辑窗口、玩家男女样本、实际居民应用后的信息面板、四类选项、儿童老人、深浅衬底、移动端、脸型/发型/服装/表情组合板和 96/64/48 原尺寸。

CI 绿色只能证明脚本通过，不证明审美。眼睛、嘴、头发和领口仍有明显问题时继续修正，不以数量或像素哈希作为美术通过证据。交付给用户要直接展示关键截图；完整 Actions Artifact 作为内部复核依据，除非用户明确要求，不再额外打包给用户下载。

## 用户对象与保存验收

编辑头像不得重建 App 会话或改变居民身份/故事。需要实际验证：给甲应用后乙不变，取消草稿不写入，关闭重开和刷新恢复，恢复默认只移除目标覆盖，存储失败不谎报成功，同对象外部更新不静默覆盖。

这套存储是 Web localStorage 示例，不冒充账号云同步或 Unity 存档。文档必须如实说明当前范围。
