# 开发与视觉审查工作流

正式回归使用 GitHub Actions：Build 与 Resident Visual Review。不依赖 Vercel、Preview 或 Production。

## 两级 Review

只修改 Face / Hair / Outfit / Expression 的 SVG 画稿、配色、局部轮廓时，可先在确认的源码版本集中修改，直接调用真实 `renderAvatar()` / Pack SVG 生成诊断图板，实际检查相关 Frame、组合和 320 / 96 / 64 / 48px，再继续聚合修正，不要求每个中间状态等待 Actions。

源码静态头像图不是概念图，但没有运行完整 React 页面，不能据此声称工坊、居民界面、LocalStorage、导入或对象绑定通过。图板必须明确标为静态诊断。

候选达到正式批次、准备推进 main，或改动 UI/存储/导入/Catalog/Registry/兼容/Head Frame/Coverage/正式 portrait/居民内容/Review 脚本时，必须走完整链路：

```text
最新 main 与项目文档 → tmp-* 聚合代码、画稿、文档
→ Build + Resident Visual Review
→ 下载同 SHA Artifact，核源码并实际看图
→ 必要时聚合修正并重跑
→ 重读 main，非 force 推进已审查提交
→ main 再跑两项并下载复核
```

允许 Git Data API create_blob/create_tree/create_commit/update_ref。禁止一文件一提交、空提交刷检查、force 覆盖并行 main。合入前 main 已有新工作时先整合再审查。纯文档改动不需要为了制造绿色状态额外跑回归；代码、数据、测试或 Review 脚本改变则按范围回归。

## Build

`.github/workflows/validate.yml` 安装依赖、构建 Content、上传 generated Artifact 并做 Web TypeScript/Vite build。generated 不手改，内容契约变更需同步 Schema、Compiler 和消费者。不得借此扩张 Unity ECS/Blob/正式 Save 架构。

### Resident Action Life 内容工作流

当前唯一近期生活链路：

```text
Content/ResidentActions/resident-action-presentations.json
→ ContentContractCompiler
→ resident-action-presentations.json / definitions.json
→ ResidentGenerator 确定性 Action Trace
→ CurrentAction + ResidentActionCompletedEvent 语义
→ Tools/ResidentActionLife/record-policy.mjs
→ RecentAction RecordPolicy
→ Resident Snapshot
→ Web “此刻 / 最近”
```

Action Presentation 只拥有 Stable ID、CurrentAction 展示短句、cooldown 和 2～4 个文本 Variant；不得拥有 Occupation / LifeStage / Wealth / Family / Weather Eligibility。targetResidentId 与 placeId 必须来自 Behaviour / Action Event，记录系统只做是否展示、去重、cooldown、VariantIndex 和容量控制。

`Tools/ResidentActionLife/record-policy.mjs` 是 Web RecordPolicy 的单一实现。`Tools/ResidentActionLife/validate.mjs` 必须独立验证确定性 Variant、cooldown、相邻去重、容量和 Target / Place 原样传递。ResidentGenerator 不得复制这套逻辑。

Web Demo 的确定性 Action Trace 只是契约验证器。正式 Schedule / Utility / Behaviour Tree、目标搜索、预约、导航与库存仍在 Unity 主工程实现。

代码、内容或 Review 变更使用 tmp-* 分支，并依次完成 Build、Resident Visual Review、同 SHA Artifact 人工检查、重读最新 main、PR merge 和 main 回归。generated 文件不手改。

居民 AI 原则同时固定：

- 财富、职业、性格、年龄通常改变 Utility / 成本 / 时间 / 机会，不作为娱乐、社交、旅行的硬白名单。
- 只有现实硬约束（钱不够、目标不存在、不可达、设施关闭、容量满、重病、正在执行互斥任务等）阻止行为。
- 不为了让 Recent UI 丰富而强制居民平均娱乐；重复劳作、没有娱乐本身可以成为玩家观察生活压力的真实结果。
- RecentAction 的丰富度应主要来自真实 Behaviour 种类，而不是大量同义 Variant。每个 Action 2～4 条文本通常足够。

## Resident Visual Review 职责

| 脚本 | 职责 |
| --- | --- |
| capture-resident-review | 生活/历史、故事、婚姻与 LifeTag 连续性 |
| capture-portrait-review | 冻结正式 fallback 的六 Frame 与组合契约 |
| capture-avatar-review + audit-packs | Catalog 全组合、头型/头发/图层/兼容、对象保存和真实 UI |
| review-avatar-integration | 入口、延迟导入、应用后切对象与原子目标切换 |
| capture-avatar-art-polish | 全 Frame × Face × Expression 腮红及负对照 |
| capture-avatar-foundation | 六框架自由创作、独立保存、草稿切换、随机与历史筛选 |
| capture-avatar-age-wardrobe | 8B1 童老逐项 UI / 画稿和保留成年样板 |
| capture-avatar-adult-wardrobe | 8B2 明确历史 ID 的点选、衣领专项、旧新隔离对照 |
| capture-avatar-theme-assets | 8D1 明确新增清单、全库描述、检索、保存/JSON/绑定、旧稿不变 |
| capture-avatar-age-themes | 8D2 童老独立新增、metadata、四 Frame 点选/保存/JSON/绑定、132 份旧稿不变 |

原脚本的有效断言保留；新资产不能通过删除旧断言来过 CI。8B2 点选和旧新变化清单只覆盖其明确历史资源，8D1 新 ID 用增量脚本及通用全组合覆盖。组合数动态计算，不写死旧素材总数。

`export-age-baseline.mjs` 从完整 SHA 的 Git archive 临时导出头像源码，用 TypeScript 执行旧 Renderer，并在 finally 清理临时目录。旧画稿只进入 Artifact，不重新注册 Pack。8B1 对照基线为 `28ad42619edb7a6abb21ca7ef8d2dee30d2afda2`，8B2 为 `59028b3afd4b24c1cc57edbe68ce13b2bd5314f9`，8D1 冻结检查为 `7ba57695c392f14d598e818beadecff877dd52f9`。

8D1 要求旧基线 88 份固定渲染不变，新 32 ID/44 份适用画稿全部点选。100 个可选资产有中文描述/关键词，文本搜索匹配真实 Catalog。32 个新项还校验显式 theme / silhouette / 相似旧 ID / 差异 / 三尺寸识别信息，并与逐项文档同行核对。新 Hair 加弧线余量抽样，衣装检查作者层。几何签名仅排除完全相同路径的换色副本，不证明审美差异。

通用密度上限为每类 22，增量审查另保留童老 12 项边界；实际成年搜索/滚动界面必须人工查看。不得把上限当作无限扩量许可。

## Artifact 和实际看图

`avatar/source-commit.txt` 记录精确 SHA；`avatar/source-and-contract.zip` 保存该提交头像源码、相关文档与 workflow。`avatar/` PNG 保留原尺寸，不参与根目录 legacy 预览压缩。

8D1 正式批次必须实际打开 `avatar/phase8d/` 四主题 `common/labor/merchant/traveler.png`、`phase8d-overview.png`、`faces-and-collars.png`、八张 `studio-<theme>-<frame>.png` 和 `bound-resident.png`。还须查看八张 studio-all 首尾截图，避免只审搜索后少数选项。native/ 保存全部 44 份新增适用画稿的三尺寸 PNG，共 132 张，逐图检查真实像素宽高。核对小尺寸和全部适用 Frame；继续查看原六框架保存/绑定与腮红、童老回归图。文字导出 `asset-descriptions.json` 只读，不手写回 Catalog。

必须区分静态 Renderer 诊断与完整浏览器真实 UI。不能把生成了截图写成看过，也不能以机器报告 PASS 替代人工查看。帽身被截断、领口悬空、肩线突折等可见问题需要继续修。

人工以桌面为主。移动端不再截图或列为必看项，390/320px 基础溢出 smoke 可保留。正式保存、导入、对象与居民逻辑测试不能用静态图替代。

## 交付

先写完成范围、main SHA、Build 和 Resident Visual Review 的真实结果、是否下载并查看同 SHA Artifact，以及新图板/实际 UI 看了哪些。必要时贴少量关键截图，区分“已实现”“候选美术待验收”“未实施”。

用户当前自行从 GitHub 拉 main 进入网页测试，**不交付压缩包**。执行者内部仍下载并审查 Artifact，此要求不变。没有对应 run 就明确未验证，不用旧 run 冒充；8D2 已获授权；不提前开始 8C 或 Unity 迁移。

## 8D2 童老扩库的增量门禁

当前从 `70ca1ccd9cc5fa75491267ce29d20043df942994` 承接 8D2，儿童、老人各 6 Hair / 6 Outfit。独立年龄源文件不复用成年画稿。旧 8B1 回归用明确历史 ID 核对重画筛选，旧 8D1 回归只把其自己的新增清单当作增量；通用 Review 仍遍历实时 Catalog、描述与原有契约，不能删除旧断言。

新 step 先从同 SHA 临时导出 baseline，再运行 capture-avatar-age-themes。必须验证 132 份旧固定配方不变、32 次新 Frame / 资产点选、24 份完整 metadata 与文档行、144 次 Frame 适用性 / 确定性回退、192 次跨 Face 图层不变、1312 个头型边界抽样位置。童老原 12 项密度上限不提高，实际最大 10。四次 JSON 往返和四种真实居民绑定不改身份或日期，恢复仅删除当前覆盖。

avatar/phase8d2/ 有 11 张静态图板、28 张真实桌面图（八张筛选、十六张未筛选首尾、四张绑定）及 96 张 native/ 原尺寸输出。下载核 source-commit 后实际打开查看，尤其是头巾外包络、低髻与耳位、衣领连接及列表末项。source-and-contract.zip 自动包含新源文件和阶段文档。候选和 main 两轮流程不变，最终美术仍交用户验收。
