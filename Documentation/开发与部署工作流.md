# 开发与视觉审查工作流

远端正式回归仍使用 GitHub Actions：Build 与 Resident Visual Review。不依赖 Vercel、Preview、Production。

## 两级 Review

本项目区分“头像静态美术短循环”和“正式浏览器／契约回归”，不再要求每一轮头像画稿修改都等待 GitHub Actions。

### 头像静态美术短循环

适用于只修改 Face / Hair / Outfit / Expression SVG 画稿、配色、局部轮廓和小尺寸表现的任务。

流程：

1. 读取最新 main、当前阶段文档和待改源码，记录当前 SHA。
2. 集中修改真实 Pack 源码。
3. 直接调用当前 Avatar Renderer（`renderAvatar()` / Pack SVG Layers）生成诊断图板。
4. 实际检查六 Frame 中受影响的组合，以及 320 / 96 / 64 / 48px。
5. 发现发型露头、帽身被切、腮红越界、衣领断开、年龄/性别辨识弱等问题时继续聚合修正。
6. 候选方向稳定后，再进入正式批次回归。

源码静态头像图板是当前代码真实 Renderer 的输出，不是概念图；但它没有运行完整 React 页面，因此不得用它证明 Avatar Workshop、Resident UI、LocalStorage、导入、对象绑定或居民逻辑已经通过。

### 正式批次 / 结构改动

以下情况仍使用原完整链路：

- 候选美术达到准备推进 main 的阶段；
- 修改 Avatar Workshop / Resident UI；
- 修改保存、恢复、草稿、LocalStorage、导入导出；
- 修改 Catalog / Registry / compatibility fallback；
- 修改 Head Frame / Hair Coverage 的正式契约或检测；
- 修改正式 ResidentPortrait fallback；
- 修改居民生活、故事、婚姻、LifeTag 或内容 Compiler；
- 修改 Review 脚本、测试或 Workflow；
- 阶段收尾或用户明确要求完整验收。

正式流程：

最新 main 与项目文档 → tmp-* → 集中改代码、素材和文档 → 一个聚合提交 → Build + Resident Visual Review → 下载 Artifact 并看图 → 必要时聚合修正 → 重读 main → 推进已审查提交 → main 重跑和复核。

可以使用 Git Data API create_blob/create_tree/create_commit/update_ref。禁止一文件一提交、空提交刷检查、force 覆盖新 main。合并前若 main 有新工作，先整合再审查。

## Build

`.github/workflows/validate.yml` 安装依赖、构建 Content、上传 generated Artifact 并执行 Web TypeScript/Vite build。generated 不手改；内容变更须同步 Schema、Compiler 与消费者。本仓库不设计 Unity ECS/Blob/正式存档。

纯文档更新不需要为了制造绿色状态而额外重跑 Build / Resident Visual Review；运行时代码、数据、测试或 Review 脚本改变时按改动范围执行相应回归。

## 截图与 Artifact

交付时必须说明截图证据类型：

- **源码静态头像图板**：直接来自当前 SHA 的真实 Avatar Renderer，可用于美术短循环；
- **Resident Visual Review Artifact**：来自完整 Vite / Playwright 浏览器链路，用于正式交互与契约回归。

不得把静态图板称为“真实 Avatar Workshop 截图”，也不得根据静态图板声称保存、导入、Resident 绑定等已经验证。



`avatar/source-commit.txt` 记录精确 SHA；`source-and-contract.zip` 保存该提交的头像源码、治理文档和 workflow。`avatar/` PNG 保留原始尺寸，不参与 legacy 根预览压缩。

当前人工审查重点为桌面美术。按用户最新要求，不再产出 `avatar/11-mobile.png`，不要求移动端人工审查；原 390/320px 溢出 smoke check 可保留但不截图。

## 自由创作 / 指定对象

自由创作保存到独立 `studio:<frame>` 键，不接触玩家/居民旧键。切换 Frame 仍走草稿确认，晚到的导入不能污染新 Frame。指定居民的年龄/性别来自居民状态，不能从创作控制改写。

继续验证甲乙保存隔离、取消不写、刷新恢复、恢复只删当前键、同对象外部更新冲突、配额失败不假成功。自由创作不重建 App、不改故事和游戏日期。

## 交付

交付先写已完成范围和当前 main SHA，并明确：

- 本轮是否只做了源码静态头像 Review；
- 静态图板实际看了哪些 Frame / 组合 / 尺寸；
- 是否执行 Build / Resident Visual Review；
- 若执行 Actions，是否下载并实际查看对应 Artifact；
- 哪些完整浏览器／存储／居民逻辑范围没有在本轮验证。

正式批次贴关键桌面真实截图和本轮诊断图；高频美术中间轮次可以只贴静态 Renderer 图板。始终区分已实现功能、候选美术/用户待验收、未完成范围。阶段文档记录样板实际审查，不自动扩量或迁 Unity。
