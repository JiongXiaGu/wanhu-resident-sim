# LifeEvent 内容格式规范

## 目标

本文件定义下一版 LifeEvent V3 的内容语义。

当前 main 代码仍使用 `wanhu.life-events.v2` 与固定 `stages[3]`。V3 尚未落地前，不新增 LifeEvent 内容；下一代码批次会一次迁移 Schema、现有 14 条内容、Compiler、Fixture 和 UI，不保留 V2 双轨读取。

## V3 基本结构

目标 Authoring：

~~~json
{
  "id": "lifeevent.example",
  "title": "发生了一件事",
  "text": "一段可以独立读懂的第一人称正文。",
  "weight": 5,
  "eligibility": {},
  "effects": {},
  "source": {
    "type": "personal",
    "label": "普通生活"
  },
  "recordToHistory": false,
  "memoryText": "只有需要进入人生经历时才提供。"
}
~~~

核心变化：

~~~text
V2
stages[3]

V3
text
~~~

LifeEvent 本身就是一次完整事件。

## Stable ID

规则继续保持：

- Stable ID 不由标题生成；
- 显示文字变化不改 ID；
- 不使用数组位置作为身份；
- 删除旧内容时不复用旧 ID。

## title

给玩家快速识别这件事。

应描述发生了什么，不写系统状态：

推荐：

~~~text
有人来给家里说亲
雨把这几日的活耽误了
第一次独自替家里办事
旧同伍进城了
~~~

避免：

~~~text
婚姻事件第一阶段
故事节点 2
普通事件 A
~~~

## text

LifeEvent 的主要近期正文。

规则：

- 第一人称；
- 约 35～80 个中文字符；
- 1～3 个短句；
- 单独阅读能理解；
- 不依赖上一 Stage；
- 不要求总结长期结局。

## eligibility

用于表达内容上需要满足的事实。

可以包括现有的：

- age；
- occupation / occupationGroup；
- gender；
- spouse / child 等家庭事实；
- requiredTags / forbiddenTags。

正式触发频率与候选算法由 Unity 实现。

## effects

描述事件发生后的内容结果。

包括：

- addTags；
- removeTags；
- structuralRequests。

结构事实优先，不用 LifeTag 重复 spouse、childCount、occupation 等已有状态。

## recordToHistory

只有长期值得回看的事件才为 true。

如果事件只是触发了一个清晰结构事实，也可以由 Unity 写 Fact Chapter，而不是强制所有结构事件都拥有文学化 memoryText。

## memoryText

只有 Story Chapter 使用。

规则见《人生经历与生活界面玩法规则 V2》。

## 连续事件

V3 不提供 stage2 / stage3。

多个事件通过：

~~~text
真实结构状态
LifeTag
年龄 / 时间条件
世界条件
~~~

重新进入候选。

示例：

~~~text
lifeevent.marriage-introduction
→ add short opportunity tag

lifeevent.marriage-agreement
→ consume previous tag
→ add next opportunity tag

lifeevent.marriage
→ formMarriage
→ add newly-married

lifeevent.newlywed-settling
→ require spouse + newly-married
→ remove newly-married
~~~

这只是内容语义示例，不要求 Web 或 Unity 实现固定状态机。

## V2 → V3 迁移规则

迁移现有 14 条时逐条判断：

### 合并

如果旧三个 Stage 只是同一件小事的起承转合：

~~~text
3 Stage
→ 1 个离散 LifeEvent
~~~

### 拆分

如果旧三个 Stage 各自是有意义、可以隔很久发生的事实：

~~~text
3 Stage
→ 多个独立 LifeEvent
→ 用事实 / Tag 串联
~~~

### 重要事件

如果旧事件已经有 memoryText：

- 保留并重新审查 memoryText；
- 只形成一个 LifeChapter；
- 不把拆出的每个后续都自动写入人生经历。

## Legacy Story Markdown

旧 `wanhu-story-v1` Markdown / StoryCompiler 不是新的 LifeEvent 内容生产入口。

现有兼容代码暂时保留，直到后续单独清理；新居民 LifeEvent 不再写入 `Content/Stories/` 三阶段 Markdown。
