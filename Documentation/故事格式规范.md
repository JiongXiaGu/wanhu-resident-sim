# 故事格式规范

## 目标

故事 Markdown 是人工创作、审查与版本管理的源文件。Web 与未来 Unity 不直接依赖 Markdown 排版，而是统一消费 StoryCompiler 生成的标准模型。

当前格式版本：`wanhu-story-v1`。

## 推荐文件位置

新故事放入：

```text
Content/Stories/<分类>/<故事标题>.md
```

现有 `居民故事/` 暂时作为 Legacy 内容源，编译器仍会读取。

文件名使用稳定故事标题，不带“修正版、最终版、重新审查版”等版本后缀。

## 推荐 Front Matter

```yaml
---
schema: wanhu-story-v1
id: story-000001
categories:
  - 家庭
  - 婚姻
importance: normal
perspective: resident
eligibility:
  required:
    - resident.adult
    - relationship.married
  forbidden: []
branchMode: random-one
---
```

### 稳定 ID

- `id` 用于程序引用，不随标题变化。
- 标题允许调整，ID 不调整。
- 现有 Legacy 故事若没有显式 ID，编译器会生成临时 `legacy-*` ID；迁移到规范目录时应补正式 ID。

## 正文结构

```md
# 故事标题

## 类型｜家庭 / 婚姻 / 人生事件

## 第一阶段｜公共起点标题

**节点时间：D0**

第一阶段正文。

---

## 分支一｜分支概括标题

<!-- branch-id: b01 -->

### 第二阶段｜第二阶段标题

**节点时间：D+3～5**

第二阶段正文。

### 第三阶段｜第三阶段标题

**节点时间：第二阶段后 D+10～20**

第三阶段正文。
```

## 结构约束

- 第一阶段只有一个，是所有分支共同起点。
- 运行时只选择一个分支。
- 每个分支必须有第二阶段和第三阶段。
- 普通故事约 3 个分支；重要故事约 4 个；核心人生事件最多 5 个。
- `branch-id` 在故事内稳定且唯一，推荐 `b01`、`b02`……
- 不应依赖“分支一/二/三”的位置作为运行时身份。

## 文本约束

- 第一阶段约 40～70 个中文字符。
- 第二、第三阶段约 40～80 个中文字符。
- 每个节点约 2～4 个短句。
- 默认第一人称。
- 分支标题是作者侧摘要，不承担剧情信息。第二阶段正文必须写出真正触发该分支的决定、发现、事故或关系变化。
- 第三阶段必须能只看第二阶段正文就理解结果。
- 避免复盘式说教结尾；优先以具体动作、物件、关系或新习惯收束。

## 时间格式

V1 接受以下写法：

```text
D0
D0，当晚
D+3
D+3～5
第二阶段后 D+10～20
```

明确正文锚点优先。例如正文写“七日后取货”，节点时间必须与七日后的事实一致。

V1 编译器保留原始时间文本，并尽可能解析出 `minDays`、`maxDays` 与 `relativeTo`。Web 当前主要展示原始时间文本；未来 Unity 使用标准化时间字段。

## 编译模型

StoryCompiler 输出：

```json
{
  "schema": "wanhu.story.v1",
  "id": "story-000001",
  "title": "故事标题",
  "categories": ["家庭"],
  "start": {
    "title": "公共起点标题",
    "time": { "raw": "D0" },
    "text": "..."
  },
  "branches": [
    {
      "id": "b01",
      "title": "分支标题",
      "weight": 1,
      "stage2": { "title": "...", "time": { "raw": "D+3～5" }, "text": "..." },
      "stage3": { "title": "...", "time": { "raw": "第二阶段后 D+10～20" }, "text": "..." }
    }
  ]
}
```

## Web / Unity 边界

```text
Markdown
  ↓
StoryCompiler + Validator
  ↓
标准 StoryDocument
  ├─ Web stories.json
  └─ Unity JSON / Binary / BlobAsset
```

Markdown 永远不进入 Unity ECS Runtime。
