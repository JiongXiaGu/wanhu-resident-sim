# LifeEvent 内容格式规范

## 目标

LifeEvent V3 继续保持“离散事件 + 事实 / Tag 弱关联”，但展示文本进一步分层：

~~~text
recentText
→ 最近
→ 一句短记录

memoryText
→ 人生经历
→ 完整长故事
~~~

不再让一个 35～80 字的中长度 `text` 同时承担两种职责。

## 目标 Authoring

下一代码批次的目标结构：

~~~json
{
  "id": "lifeevent.example",
  "title": "第一次独自接下一户出诊",
  "recentText": "第一次独自背着药箱去给人看病。",
  "weight": 5,
  "eligibility": {},
  "effects": {},
  "source": {
    "type": "work",
    "label": "医馆出诊"
  },
  "recordToHistory": true,
  "memoryText": "那回师长正好不在铺里……"
}
~~~

当前 main 仍使用 V3 过渡字段 `text`。

下一代码批次直接：

~~~text
text
→ recentText
~~~

迁移当前全部 LifeEvent。

不保留 `text` fallback，不维护双轨兼容；需要旧格式时查 Git 历史。

## Stable ID

- Stable ID 不由标题生成；
- 显示文字变化不改 ID；
- 不使用数组位置作为身份；
- 删除旧内容时不复用旧 ID。

## title

`title` 是事件和 LifeChapter 的简短标题。

用途：

- Authoring；
- DEV / Review；
- Story Chapter 时间轴；
- 必要的内容检索。

普通“最近”列表不显示 title。

## recentText

`recentText` 是近期生活 Presentation。

规则：

- 必填；
- 一句话；
- 通常约 12～36 个中文字符；
- 可以独立读懂；
- 适合快速扫读；
- 不包含完整故事过程；
- 不包含系统标签；
- 不使用标题 + 正文两层结构。

例如：

~~~text
有人来给家里说亲。
和城南张家姑娘成了婚。
旧同伍进城来看我。
第一次独自背着药箱去给人看病。
~~~

如果内容只是已有 Behaviour 的完成事实，应优先由 Action Presentation 提供，而不是重复建立 LifeEvent。

## eligibility

用于表达故事 / 事件成立需要的事实：

- age；
- occupation / occupationGroup；
- gender；
- spouse / child 等家庭事实；
- requiredTags / forbiddenTags；
- 其它以后明确进入内容契约的世界条件。

正式触发概率与候选算法由 Unity 实现。

## effects

可以描述：

- addTags；
- removeTags；
- structuralRequests。

结构事实优先，不用 LifeTag 重复 spouse、childCount、occupation 等当前状态。

## recordToHistory

表示该事件发生后是否值得形成 Story Chapter。

`recordToHistory = false`：

~~~text
recentText
→ 最近
→ 淘汰
~~~

`recordToHistory = true`：

~~~text
recentText
→ 最近

memoryText
→ LifeChapter
→ 人生经历
~~~

## memoryText

只允许用于 Story Chapter。

规则：

- 当 `recordToHistory = true` 时必须提供；
- 第一人称；
- 约 80～180 个中文字符；
- 一件完整往事；
- 不用于“最近”；
- 不由 recentText 自动扩写或拼接；
- 不扫描旧 Stage 生成。

## Fact Chapter

成婚、添孩子、搬家、换职业等结构事实也可以形成 Fact Chapter。

如果同一件事已有 Story Chapter，不再生成同义 Fact Chapter。

## Story Chapter 的形成

Tag / 结构事实只决定候选资格。

正确链路：

~~~text
结构事实 / LifeTag / 年龄 / 职业等
→ LifeEvent Eligibility
→ 事件真正发生
→ recordToHistory?
   ├─ false → 只进入最近
   └─ true  → 写入 LifeChapter
~~~

打开人生经历页面时不根据当前 Tag 重新生成过去。

## 连续事件

V3 不提供 stage2 / stage3。

多个事件通过：

~~~text
真实结构状态
LifeTag
年龄 / 时间条件
世界条件
~~~

重新进入候选。

例如：

~~~text
marriage-introduction
→ courtship-open

marriage-agreement
→ betrothed

marriage-completion
→ spouse
→ newly-married

newlywed-settling
→ require spouse + newly-married
→ remove newly-married
~~~

这只是候选资格链，不是固定 Story Thread。

## 内容生产分类

新增内容前先判断属于哪一类：

### A. Behaviour Presentation

真实行为已经存在。

→ 补 Action Presentation。

### B. Recent-only LifeEvent

不是普通 Behaviour，但只值得近期知道。

→ recentText；
→ recordToHistory = false；
→ 不写 memoryText。

### C. Life Story

多年后仍值得知道。

→ recentText；
→ recordToHistory = true；
→ memoryText；
→ 必要时产生 Tag / 结构变化。

不要继续生产“35～80 字、既不像日志又不像人生故事”的中间层正文。

## Legacy Story Markdown

旧 `wanhu-story-v1` Markdown / StoryCompiler 不是新的 LifeEvent 内容生产入口。

现有兼容代码后续单独清理；新的居民故事直接进入 LifeEvent / LifeChapter 内容链。
