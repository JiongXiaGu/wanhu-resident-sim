# 居民面板与生活事件 V2

## 目标

玩家点击居民时，界面不是替居民生成一段“综合近况”，而是直接展示可验证的事实与经历：

1. 他是谁？
2. 他属于哪里？
3. 他现在在做什么？
4. 他正在经历或最近发生了什么？
5. 他过去有哪些值得记住的人生章节？

居民的一生由多个不同阶段发生的故事共同组成，而不是长期绑定一条“当前故事”。

---

## 两种玩家浏览模式

Resident Panel 明确分成两种时间尺度，不在同一画面中混合。

### 当前生活模式

用于回答“这个人现在过得怎么样”。

```text
Resident Panel / 当前生活
├─ Identity
├─ World Links
├─ Current Activity
├─ Current / Recent LifeEvent
├─ Recent Routine
└─ Follow / Life History Entry
```

这里允许显示此刻、正在经历、最近发生和普通 Routine。

### 人生经历模式

玩家点击“人生经历”后，面板切换为独立的人生浏览模式，而不是在当前生活下面追加一个抽屉。

```text
Resident Panel / 人生经历
├─ Identity
├─ World Links
├─ Biography Header
│  ├─ 某某的一生
│  └─ 当前年龄 / 已记录章节数
├─ Life Stage Groups
│  ├─ 童年
│  ├─ 少年
│  ├─ 青年
│  ├─ 壮年
│  ├─ 中年
│  └─ 晚年
├─ Life Chapter Timeline
│  ├─ Fact Chapter
│  └─ Story Chapter → 可展开完整三阶段故事
├─ Now Marker
└─ Follow / Return To Life
```

人生经历模式必须隐藏：

- `Current Activity / 此刻`
- 当前或刚完成的 LifeEvent
- `Routine / 最近`
- 任何仅用于说明“这几天在做什么”的琐事

原因是人生页的目标不是继续浏览日志，而是回答：

> 这个人是怎么走到今天的？

玩家退出人生经历后，再回到当前生活模式。

---

## 不再保存独立“近况摘要”

不再定义居民级的 `Current Summary / 近况` 字段，也不在 LifeEvent Stage 中保存 `summary`。

原因是一个居民可能同时受到工作、家庭、城市工程、天气和个人故事影响。若强行把这些状态压缩成一句“近况”，就需要额外解决优先级、冲突、过期和文本组合问题，最终会形成另一套难维护的状态摘要系统。

当前生活面板直接展示：

```text
此刻
正在木作铺里做一件新活

正在经历
[当前 LifeEvent]

最近
[若干 Routine]
```

事件结束后，`Current Activity` 回到职业 / 当前状态推导，不需要再补一句“已经恢复原来的生活”。

---

## 三层信息结构

### Routine

普通生活的小记录，例如买东西、收工、整理铺子。

- 数量多
- 生命周期短
- 使用有限容量
- 不进入人生经历
- 人生经历模式完全不显示

### LifeEvent

当前或最近发生的一件具体事情。

- 通常 3 个阶段
- 当前阶段完整展示
- 同一事件的旧阶段只作为轻量前情
- 可以临时覆盖 `Current Activity`
- 默认不会永久进入人生经历
- 尚未完成的当前故事不会提前出现在人生时间轴

### Life Chapter

值得长期记住的人生章节。

- 成婚、开始营生等事实变化
- 服役、第一次独立做活等重要故事
- 长期保存在 `majorLifeHistory`
- 在人生经历模式中按发生年龄展示

因此：

```text
Routine ≠ LifeEvent ≠ Life Chapter
```

不是所有发生过的事情都值得永久保存。

---

## LifeEvent V2

### 基本字段

```text
id
weight
eligibility
source?
recordToHistory?
stages[3]
  delayDays
  title
  text
  activityOverride?
```

LifeEvent V2 不包含 `summary` 字段。Stage 自身的 `title + text` 负责表达当下发生的事情；需要影响“此刻”时使用 `activityOverride`。

### `recordToHistory`

只有真正值得成为人生章节的事件才设置：

```json
{
  "recordToHistory": true
}
```

例如：

- 被征召服役
- 第一次独立完成正式工作
- 第一次独自替家里办事
- 孩子开始入学
- 晚年形成新的稳定生活方式

普通天气、订单增多、施工绕路等事件默认只属于当时生活，不进入永久人生历史。

完成后的重要 LifeEvent 用 `sourceEventId` 写入 `majorLifeHistory`。人生面板展开该章节时，再通过 `sourceEventId` 回查 LifeEvent Definition，不把完整三阶段正文复制进每个居民存档。

---

## 当前事件的可见周期

当前 Web 验证规则：

- Stage 1 / Stage 2：属于“正在经历”。
- Stage 3：短时间内属于“最近发生”。
- 完成 14 天以后：从当前生活模式退出。
- 若 `recordToHistory = true`：完成后仍可在人生经历模式长期查看。
- 若未开启：只留下短期生活痕迹，不进入永久历史。

人生模式只读取已沉淀的 Life Chapter，不读取当前生活区块。

---

## 人生由多次故事抽取组成

居民不在出生时确定一条固定人生剧本。

```text
居民状态
+
年龄阶段
+
职业 / 家庭条件
+
世界状态
+
过去的重要经历
↓
Eligible Story Pool
↓
低频加权抽取
↓
Story Thread / LifeEvent
↓
完成后按重要度决定是否成为 Life Chapter
```

当前 Web 快照生成器按年龄阶段对 `recordToHistory` 故事进行确定性抽取：

```text
10～17
18～25
26～39
40～57
58+
```

同一 Seed 会稳定得到相同历史；不同居民不会固定拥有相同数量的精彩故事。

---

## 人生经历 UI

人生经历的计数表示人生章节数量，不表示 LifeEvent Stage 数量，也不包括 Routine。

默认先展示人生骨架，而不是把所有正文一次铺开：

```text
少年
14岁 · 第一次独自替家里办事        展开故事

青年
22岁 · 成了家                      人生节点

壮年
27岁 · 轮到我去服役                展开故事
34岁 · 开始做木工                  人生节点

39岁 · 如今
```

只显示确实拥有章节的人生阶段；没有故事的阶段允许留白，不伪造事件填满时间轴。

### 事实章节

如“成了家”“开始做木工”“搬到某坊”只显示一行，不伪造文学正文。

### 故事章节

来自预制 LifeEvent 的章节可以展开完整故事。展开后的三个节点不用显示 `Stage 1 / Stage 2 / Stage 3`，而使用叙事化顺序：

```text
起初
名册上轮到我了
正文……

后来
每天都在官道上搬石填土
正文……

最后
终于回到家里
正文……
```

章节展开是“翻看一段往事”，不是开发进度查看器。

### 如今

时间轴末尾始终保留一个轻量“如今”节点，表示过去章节汇聚到当前居民，而不是把当前 LifeEvent 塞进历史。

---

## 多故事线的边界

“多故事线”指一个居民的一生由多条独立或弱关联 Story Thread 组成，不代表建立完整社会关系图。

推荐关系：

```text
约 80% 故事独立完成
约 20% 重要故事留下可复用的人生痕迹
```

后续可通过轻量 `LifeTag / Story Anchor` 让未来故事读取过去结果，例如“曾经服役”“曾独立开铺”“曾经迁居”。这些标签只服务稀疏故事筛选，不做高频关系传播。

---

## 性能边界

常规故事选择只读取：

```text
Resident 自己的数据
+ Household 少量冷数据
+ Global / Definition 只读数据
+ 少量已保存人生章节 / 标签
```

不查询朋友、不遍历邻居、不沿家谱传播状态。

居民系统的重点是：

> 用少量稳定数据和稀疏故事，让玩家相信这个人过去真的生活过。
