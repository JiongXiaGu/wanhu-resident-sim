# 居民面板与生活事件 V2

## 目标

玩家点击居民时，界面首先回答的是“这个人最近过得怎么样”，而不是“这个 NPC 身上挂着哪篇故事”。

居民面板固定围绕五个问题组织：

1. 他是谁？
2. 他属于哪里？
3. 他现在在做什么？
4. 他最近过得怎么样？
5. 他过去经历过什么？

这五个问题比增加更多数值属性更重要。

---

## 玩家面板结构

```text
Resident Panel
├─ Identity
│  ├─ 头像
│  ├─ 姓名 / 年龄 / 职业
│  └─ 居住区域 / 家庭摘要
├─ World Links
│  ├─ 住处
│  ├─ 工作地
│  └─ 家人
├─ Current Activity
├─ Current Summary
├─ Recent Life
│  ├─ 当前 LifeEvent
│  ├─ 同一事件前情
│  └─ 2～4 条 Routine
├─ Family Drawer / Life History
└─ Follow Action
```

玩家面板不显示 Story ID、Branch、Stage、D+、分支数量和预制剧情进度。

---

## World Links

居民面板顶部提供三个轻量入口：

- `住处`：定位到居民所在 Household / Home。
- `工作地`：定位到当前 Workplace。
- `家人`：按 Household 冷数据展开家庭成员，可继续选择另一个居民。

这些入口只读取现有 ID，不引入居民关系传播或高频网络计算。

家庭数据依然是冷数据：只有玩家打开面板时才查询 Household 与居民引用。

---

## “近况”不是新模拟系统

近况是一段玩家摘要，不是新的幸福度、情绪或 Needs 系统。

它可以由当前 LifeEvent Stage、职业状态和家庭状态直接推导，例如：

```text
排水施工挡住门面，生意暂时受了影响。
```

```text
正在城北官道服役，原来的工作暂时停下。
```

```text
最近日子平稳，没有什么特别的变化。
```

目的只是让玩家在 1～2 秒内理解这个居民当前的生活状态。

## LifeEvent V2

### 为什么引入新的 LifeEvent

现有 Legacy Story 最初是按“点击一次读一段”的独立文学事件设计，节点正文通常为 40～80 字。

在 400px 居民面板里，这些正文会过度占据视觉中心，导致玩家产生：

> 点一个居民 = 打开一篇故事

而不是：

> 点一个居民 = 看看这个人最近过得怎么样

因此默认游戏验证不再直接使用 Legacy Story 作为居民面板内容源。

Legacy Story 继续保留：

- 作为已有创作素材
- 在完整故事审查器中继续可读
- 后续可以挑选其中适合的题材重写成 LifeEvent V2

不要求为了兼容旧格式而牺牲玩家体验。

### V2 内容预算

每个 LifeEvent 仍然可以有 3 个时间阶段，但玩家文本更短：

- `title`：尽量 8～18 个中文字符
- `text`：通常 25～55 个中文字符，1～2 个短句
- `summary`：通常 15～30 个中文字符
- `activityOverride`：只在事件确实改变居民当前活动时填写

V2 的目标不是文学篇幅，而是形成一条可连续追踪的人生近况。

### 连续展示

同一 LifeEvent 的三个 Stage 在 UI 中必须被视觉上视为同一件事。

当前 Stage 完整展示，前一 Stage 只保留轻量前情：

```text
7日前
工人铺了一条临时木板路
正文……

└ 10日前 · 街口开始挖排水沟
```

不要把三个 Stage 展示成三个同等重量的独立新闻。

---

## Source：把居民和城市连起来

LifeEvent 可以携带一个很轻的 `source`：

```json
{
  "type": "city",
  "label": "北市坊排水工程"
}
```

支持的 V2 来源：

- `city`：城市建设或政策变化
- `family`：家庭内部变化
- `work`：营生和工作环境
- `weather`：天气 / 节令
- `personal`：普通个人生活

Source 的价值不是建立复杂依赖，而是让玩家明确感受到：

> 我建设的城市，正在改变具体居民的生活。

未来 Source 可以继续扩展稳定 ID，但 V2 先只验证类型和显示名称。

---

## Story / LifeEvent 的职责分离

当前仓库允许两种内容并存：

### Legacy Story

- Markdown
- 更适合作者审查和文学内容储备
- 保留完整三阶段和多分支
- 默认不进入玩家 Resident Panel

### LifeEvent V2

- 结构化 Definition
- 文本短
- 面向玩家居民面板
- 可以有简单 Eligibility / Source / Activity Override
- 运行时只需要给某个居民选择一条事件线

确认 LifeEvent V2 的体验稳定以后，再决定哪些 Legacy Story：

- 重写并迁移
- 只保留为素材
- 彻底删除

## 性能边界

LifeEvent 不改变居民模拟的并行原则。

常规选择只读取：

```text
Resident 自己的数据
+ Household 的少量冷数据（仅需要家庭条件时）
+ Global / Definition 只读数据
```

不查询朋友、不遍历邻居、不沿家谱传播状态。

事件如果暂时影响居民“此刻”的显示，只使用 `activityOverride`，不需要运行完整日程模拟。

未来真正修改职业、家庭、居住地时，再通过低频结构命令系统处理。

---

## 沉浸感优先级

居民系统后续优先保证以下链路能被玩家感知：

```text
人
↕
家庭
↕
住处
↕
工作
↕
城市变化
↕
人生经历
```

这些关联比扩大 Needs、情绪传播、社会关系网更符合《万户天工》的性能和玩法目标。
