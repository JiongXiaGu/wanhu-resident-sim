# 居民面板与生活事件 V2

## 目标

玩家点击居民时，界面直接展示事实、当前生活和已经沉淀的人生经历，不生成一段人工拼接的“综合近况”。

Resident Panel 需要回答：

1. 他是谁？
2. 他属于哪里？
3. 他现在在做什么？
4. 他正在经历或最近发生了什么？
5. 他过去经历过哪些值得记住的事情？

---

## 两种玩家浏览模式

### 当前生活模式

回答：**这个人现在过得怎么样？**

```text
Resident Panel / 当前生活
├─ Identity
├─ World Links
├─ Current Activity
├─ Current / Recent LifeEvent
├─ Recent Routine
└─ Follow / Life History Entry
```

这里允许显示：

- `此刻`；
- `正在经历 / 最近发生`；
- 少量 RecentAction。

### 人生经历模式

回答：**这个人是怎么走到今天的？**

玩家点击“人生经历”后，面板进入独立浏览模式，不在生活页下面追加历史抽屉。

```text
Resident Panel / 人生经历
├─ Identity
├─ World Links
├─ Biography Header
│  ├─ 某某的一生
│  └─ 当前年龄 / 已记录章节数
├─ Continuous Life Timeline
│  ├─ 13岁 · 一件事
│  ├─ 18岁 · 一件事
│  ├─ 25岁 · 一件事 → 可展开回忆
│  ├─ 32岁 · 一件事
│  └─ …
├─ Now Marker
└─ Follow / Return To Life
```

人生经历模式必须隐藏：

- `Current Activity / 此刻`；
- 当前或刚完成的 LifeEvent；
- `Routine / 最近`；
- 任何只用于说明“这几天在做什么”的琐事。

人生页不再显示“童年 / 少年 / 青年 / 壮年 / 中年 / 晚年”等分组。玩家从最年轻的节点开始往下滚动，按年龄从小到大阅读这个人的一生。

---

## 不再保存独立“近况摘要”

不定义居民级 `Current Summary / 近况`，也不在 LifeEvent Stage 中维护 `summary`。

当前生活直接展示：

```text
此刻
正在木作铺里做一件新活

正在经历
[当前 LifeEvent]

最近
[若干 Routine]
```

一个居民可能同时受职业、家庭、城市工程、天气和个人故事影响。若再拼一条“综合近况”，会额外产生优先级、冲突、过期和文本组合问题，因此取消。

---

## 三层信息结构

### Routine

`RecentAction` 是居民真实完成行为的近期精选记录。

来源固定：

```text
Behaviour Complete
→ ResidentActionCompletedEvent
→ RecentActionRecordSystem
→ 最近 UI
```

它不再是独立内容抽取系统，也不做职业 / 年龄 / 家庭 / 天气 Eligibility。普通 RecentAction 会自然淘汰，不进入人生经历。

### LifeEvent

当前或最近发生的一件连续事情。

- 通常 3 个阶段；
- 当前阶段完整展示；
- 旧阶段只保留轻量前情；
- 可以临时覆盖 `Current Activity`；
- 默认不会永久进入人生经历；
- 尚未完成的故事不会提前出现在人生时间轴。

### Life Chapter

值得长期回看的过去。

- 成婚、开始营生等事实变化；
- 服役、第一次独立做活、孩子入学等重要故事；
- 在人生页里 **一个 Chapter = 一个时间轴节点 = 一件事**。

因此：

```text
Routine ≠ LifeEvent ≠ Life Chapter
```

---

## LifeEvent V2

当前原型核心字段：

```text
id
weight
eligibility
source?
recordToHistory?
memoryText?
effects?
stages[3]
  delayDays
  title
  text
  activityOverride?
```

### `stages`

服务当前生活模式。

玩家在故事进行中逐步看到三个阶段，理解“这件事正在怎么发展”。

### `memoryText`

服务人生经历模式。

只要 LifeEvent 会形成长期 Life Chapter，就必须提供一段完整的第一人称回忆文本。

例如：

```text
25岁 · 孩子到了该认字的年纪

我开始问附近哪家私塾合适。孩子那阵子总爱盯着牌匾上的字，我和家里商量，想着该让他正经认字了。送到门口时他还一直回头看，先生领进去以后，我反倒在门外站了一会儿才走。后来有一天回家路上，他忽然把一家铺子的招牌念了出来，虽然只认得几个字，也够他高兴一路。
```

`memoryText` 不是三个 Stage 原文的机械拼接，也不显示：

```text
Stage 1 / Stage 2 / Stage 3
起初 / 后来 / 最后
来源标签
```

它应该像居民自己回想一件已经发生过的事情。

### 哪些事件必须有 `memoryText`

- `recordToHistory: true`；
- 或具有会形成长期人生变化的 Prototype Effect，例如成婚。

普通天气、短期忙碌、邻里小事等不需要为了人生页单独写回忆。

---

## 当前事件的可见周期

Web 原型规则：

- Stage 1 / Stage 2：`正在经历`；
- Stage 3：短时间内显示为 `最近发生`；
- 完成约 14 天后：从当前生活模式淡出；
- 若成为 Life Chapter：以后仍能在人生经历里看到；
- 普通事件结束后不强行留下永久记录。

---

## 人生经历 UI

人生经历计数表示 Life Chapter 数量，不表示 LifeEvent Stage 数量，也不包括 Routine。

### 时间轴顺序

所有节点按年龄升序：

```text
13岁 · 第一次独自替家里办事       展开
18岁 · 开始做木工
23岁 · 成了家
27岁 · 轮到我去服役               展开
31岁 · 家里添了孩子
37岁 · 如今
```

不再插入“少年 / 青年 / 壮年”等分类标题。

### 事实节点

如：

```text
23岁 · 成了家
34岁 · 开始做木工
```

只显示 `年龄 + 标题`，不显示“人生节点”等系统标签，也不伪造正文。

### 故事节点

默认收起。玩家感兴趣时只展开这一件事的 `memoryText`。

同一节点里不再放三个历史小故事；三个 Stage 只是当年事情发生时的过程，最终在人生页沉淀成一段完整回忆。

### 如今

时间轴末尾保留轻量“如今”节点，连接过去与当前生活，但不把当前 LifeEvent 混进历史。

---

## 人生由多次故事组成

居民不是出生时绑定一条完整人生剧本。

```text
年龄
+
职业 / 家庭
+
LifeTag
+
世界状态
↓
Eligible Story Pool
↓
低频选择 Story Thread
↓
当前生活中逐阶段发生
↓
重要结果形成一个 Life Chapter
```

故事选择内部仍可使用年龄阶段做候选池优化，但这些内部阶段 **不等于人生页 UI 分组**。

---

## Prototype Effect

Web Demo 允许故事完成后直接改变原型状态，用来验证“故事真正改变人物”是否好玩。

当前可以验证：

```text
LifeTag 增减
changeOccupation
moveHousehold
formMarriage
```

结构型故事实际发生以后，应：

```text
故事完成
↓
居民状态变化
↓
形成一个人生节点
↓
新的 Family / Occupation / LifeTag 条件进入候选池
↓
未来可能出现后续故事
```

这只是 Web 原型，不代表未来 Unity 的实现架构。

---

## 多故事线边界

一个居民的一生可以由多个独立或弱关联 Story Thread 组成，但不因此建立完整社会关系图。

推荐：

```text
大多数故事独立结束
少量重要故事留下 LifeTag / Story Anchor
```

过去的结果可以在多年后产生回响，但常规故事选择不需要遍历全文历史或整座城市的人际关系。

---

## Web 验收重点

当前 Resident Panel 主要验证：

- 生活页是否像“现在正在生活”；
- 人生页是否像“从小时候一路读到现在”；
- 每个历史节点是否只讲一件事；
- `memoryText` 是否像角色自己的回忆；
- 普通琐事是否会自然淡出；
- 重要经历是否真的影响后来；
- 玩家是否愿意主动展开某一段过去。
