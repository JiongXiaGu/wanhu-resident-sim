# 人生经历与生活界面玩法规则 V2

## 目标

居民面板只提供三个玩家时间尺度：

~~~text
此刻
最近
人生经历
~~~

行为触发、事件触发与运行时状态由 Unity 实现；Resident Content Lab 只验证内容和阅读体验。

## 此刻

只显示真实 CurrentAction。

回答：

> 他现在在做什么？

不显示故事摘要，不由 LifeEvent 覆盖。

## 最近

“最近”回答：

> 他最近都做了些什么？

统一显示：

- RecentAction；
- RecentLifeEvent。

二者按时间混合，但每一条只是一句短文本。

例如：

~~~text
2日前  去朋友家坐了一阵。
4日前  有人来给家里说亲。
7日前  去市上买了些粮。
~~~

这里不显示长正文、memoryText、来源标签或技术分类。

“最近”是快速扫读区，不是故事阅读区。

## 人生经历

人生经历回答：

> 这个人过去经历过什么，怎么走到今天？

规则：

1. 一条纵向时间轴；
2. 按年龄从小到大；
3. 不使用童年 / 少年 / 青年 / 壮年 / 中年 / 晚年 UI 分组；
4. 一个节点只代表一件事；
5. Fact Chapter 只显示年龄 + 标题；
6. Story Chapter 默认收起；
7. 展开 Story Chapter 后才显示完整 `memoryText`；
8. 不显示 Stage、来源标签、事件系统结构；
9. 时间轴末尾保留“如今”。

## Memory Text

`memoryText` 只服务人生经历。

它是本系统的长故事文本。

推荐：

- 第一人称；
- 约 80～180 个中文字符；
- 保留关键人物、动作、地点或物件；
- 像多年以后回忆一件完整往事；
- 不使用 Stage 结构；
- 不机械使用“起初 / 后来 / 最后”；
- 不总结人生大道理。

禁止把 memoryText 显示到“最近”。

## recentText

近期展示使用独立短句。

目标：

- 一句话；
- 快速扫读；
- 通常约 12～36 个中文字符；
- 不承担完整故事；
- 不和 memoryText 复用同一段文字。

例如：

~~~text
recentText:
和城南张家姑娘成了婚。

memoryText:
那阵子姨母替我牵了线……
~~~

## 事实优先

成婚、添孩子、搬家、换工作等结构事实本身就可以形成 Fact Chapter。

如果同一事件已经用 memoryText 形成 Story Chapter，不再生成同义 Fact Chapter。

## 人生故事如何形成

人生经历不是打开 UI 时根据当前 Tag 动态生成。

正确顺序：

~~~text
结构事实 / LifeTag / 年龄 / 职业 / 家庭条件
→ 决定某个人生故事是否有资格发生
→ 事件真正发生
→ 写入 LifeChapter
→ 以后长期读取这条 Chapter
~~~

因此 Tag 是故事候选的输入，不是历史文本本身。

资源库以后增加新故事，也不能让旧存档里的居民凭空多出一段过去。

## 人生密度

人生经历允许稀疏。

不同居民可以：

- 青年经历较多；
- 中年才出现转折；
- 一生只有几个重要节点；
- 很长时间没有值得长期记录的故事。

不要为了填满时间轴给每个阶段强行安排重大事件。

## 连续性

人生连续性不依赖 Story Thread。

优先读取：

~~~text
真实结构事实
→ spouse / child / occupation / household 等

长期 LifeTag
→ served-military / opened-shop / migrated 等

短期机会 Tag
→ newly-married / betrothed 等
~~~

多个离散事件可以通过这些事实形成弱关联故事链。

同一个 Tag 可以解锁多个候选，不要求唯一下一集。

## Web 验收重点

主要判断：

- “此刻 / 最近 / 人生经历”是否一眼能区分；
- “最近”是否能在几秒内扫完；
- 最近记录是否全部是短句；
- 人生节点数量是否可信；
- memoryText 是否只出现在 Story Chapter；
- 每个 Chapter 是否只讲一件事；
- 结构事实和 Story Chapter 是否重复；
- Tag / 结构事实是否合理影响后续故事资格；
- 打开人生页是否只读取已发生的 Chapter，而不是即时重算过去。
