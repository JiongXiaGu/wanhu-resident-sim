# 人生经历与生活界面玩法规则 V2

## 目标

居民面板只提供三个玩家时间尺度：

~~~text
此刻
最近
人生经历
~~~

行为触发、事件触发与运行时状态由 Unity 实现；Resident Content Lab 只验证内容和阅读体验。

## 此刻

只显示真实 CurrentAction。

不显示故事摘要，不由 LifeEvent 覆盖。

## 最近

“最近”统一显示：

- RecentAction；
- 近期 LifeEvent。

二者按时间混合，不分成“最近发生”和“最近”两个区域。

普通近期内容会自然淘汰。

## 人生经历

人生经历回答：

> 这个人过去经历过什么，怎么走到今天？

规则：

1. 一条纵向时间轴；
2. 按年龄从小到大；
3. 不使用童年 / 少年 / 青年 / 壮年 / 中年 / 晚年 UI 分组；
4. 一个节点只代表一件事；
5. Fact Chapter 只显示年龄 + 标题；
6. Story Chapter 默认收起，展开后只显示一段 memoryText；
7. 不显示 Stage、来源标签、事件系统结构；
8. 时间轴末尾保留“如今”。

## Memory Text

`memoryText` 只服务人生经历。

它应该像居民多年后回忆一件完整往事，而不是系统日志。

推荐：

- 第一人称；
- 约 80～180 个中文字符；
- 保留关键人物、动作、地点或物件；
- 不使用“Stage 1 / 2 / 3”；
- 不机械使用“起初 / 后来 / 最后”；
- 不总结人生大道理。

只有真正需要长期保留的 Story Chapter 才需要 memoryText。

## 事实优先

成婚、添孩子、搬家、换工作等结构事实本身就可以形成 Fact Chapter。

如果同一个 LifeEvent 已经用 memoryText 形成 Story Chapter，不再重复生成同义 Fact Chapter。

## 人生密度

人生经历允许稀疏。

不同居民可以：

- 青年经历多；
- 中年才出现转折；
- 一生只有几个重要节点；
- 很长时间没有值得长期记录的故事。

不要为了填满时间轴给每个阶段强行安排重大事件。

## 连续性

人生连续性不依赖长 Story Thread。

优先读取：

~~~text
真实结构事实
→ spouse / child / occupation / household 等

长期 LifeTag
→ served-military / first-independent-task 等

短期机会 Tag
→ newly-married 等
~~~

多个离散 LifeEvent 可以通过这些事实自然形成故事链。

## Web 验收重点

主要判断：

- “此刻 / 最近 / 人生经历”是否一眼能区分；
- 最近列表混合行为和事件后是否自然；
- 人生节点数量是否可信；
- 每个节点是否只讲一件事；
- memoryText 是否像角色自己的回忆；
- 结构事实和 Story Chapter 是否出现重复；
- 连续查看多个居民后是否明显模板化。
