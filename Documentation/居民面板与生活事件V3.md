# 居民面板与生活事件 V3

## 目标

Resident Panel 当前生活信息只保留：

~~~text
此刻
最近
人生经历
~~~

三个区域承担不同的信息密度：

~~~text
此刻       即时状态
最近       快速扫读
人生经历   深度故事
~~~

玩家不需要理解 Action、LifeEvent、Story、Stage 等内部系统名。

---

## 当前生活模式

~~~text
Resident Panel
├─ Identity / Portrait
├─ World Links
├─ 此刻
├─ 最近
└─ 人生经历入口
~~~

### 此刻

只读取真实 `CurrentAction`：

~~~text
此刻
正在井边打水
~~~

LifeEvent 不覆盖“此刻”。

### 最近

只有一个近期列表。

数据来源可以包括：

~~~text
RecentAction
RecentLifeEvent
~~~

但每一项统一只显示：

~~~text
时间 + 一句短文本
~~~

例如：

~~~text
最近

2日前  去朋友家坐了一阵。
4日前  有人来给家里说亲。
7日前  去市上买了些粮。
~~~

即使是重要事件：

~~~text
3日前  和城南张家姑娘成了婚。
~~~

也不在这里展开长故事。

---

## 最近区域的 UI 规则

“最近”的目标是效率，而不是沉浸阅读。

因此：

- 一条记录只对应一句文本；
- 不显示 LifeEvent 标题 + 正文两层；
- 不显示 memoryText；
- 不做长故事卡；
- 不显示来源标签；
- 不显示 Action / LifeEvent / Story / Stage 技术分类；
- RecentAction 与 RecentLifeEvent 使用接近的视觉密度；
- 按时间从近到远排序；
- 普通近期内容自然淘汰。

桌面宽度下优先保持一行；文本稍长时允许自然折成两行，但内容本身仍必须是一句话。

---

## RecentAction

RecentAction 是真实 Behaviour 完成事实的短展示：

~~~text
3日前  去井边挑了水回来。
~~~

它不会进入人生经历。

Action Presentation 的丰富度跟随真实 Unity Behaviour 增长，不为了 UI 丰富度创造不存在的行为。

---

## RecentLifeEvent

RecentLifeEvent 用于行为日志无法直接表达的近期事实：

~~~text
有人来给家里说亲。
孩子第一天进了私塾。
旧同伍进城来看我。
今日成了婚。
~~~

它与 RecentAction 在玩家视角下都是“最近发生的一件事”。

数据来源可以不同，但 UI 不把这种差别展示出来。

---

## 人生经历模式

点击“人生经历”后进入深度阅读：

~~~text
某某的一生

13岁 · 第一次独自替家里办事      [可展开]
18岁 · 开始做木工
23岁 · 成了家                     [可展开]
27岁 · 服役结束回家               [可展开]
31岁 · 家里添了孩子
……
如今
~~~

规则：

- 一条纵向时间轴；
- 按年龄从小到大；
- 不按少年 / 青年 / 壮年分 UI 组；
- 一个节点只代表一件事；
- Fact Chapter 只显示年龄 + 标题；
- Story Chapter 展开一段 `memoryText`；
- 末尾保留“如今”。

人生模式隐藏：

- CurrentAction；
- “最近”；
- 其它短期生活信息。

---

## 最近与人生经历不是同一份文本

同一个重要事件可以拥有两种 Presentation：

~~~text
成婚发生
├─ recentText
│  └─ “和城南张家姑娘成了婚。”
│     → 最近
└─ memoryText
   └─ 一段完整第一人称回忆
      → 人生经历
~~~

两者不能复用同一段中长度正文。

“最近”负责效率，“人生经历”负责故事。

---

## 人生故事的资格来源

Story Chapter 的候选资格可以读取：

~~~text
真实结构事实
长期 LifeTag
短期机会 Tag
年龄 / 职业 / 家庭 / 世界条件
~~~

但故事一旦真正发生并写入 LifeChapter，之后打开人生页面只读取已发生 Chapter。

UI 不根据当前 Tag 即时重新生成过去。

---

## 结构事实避免重复节点

例如成婚：

如果同一件事已经形成带 memoryText 的 Story Chapter，就不要同时再显示同义 Fact Chapter。

优先原则：

- 有值得阅读的 memoryText → Story Chapter；
- 只是结构事实 → Fact Chapter。

不要出现：

~~~text
23岁 · 成婚
23岁 · 这门亲事定下来了
~~~

---

## Content Lab Fixture

Web 只需要固定 Fixture：

- CurrentAction；
- RecentAction[]；
- RecentLifeEvent[]；
- LifeChapter[]；
- LifeTag / 结构状态；
- 后续故事 Eligibility 检查。

Web 不需要：

- Story Thread；
- Stage 推进；
- 正式 LifeEvent Trigger；
- Utility / Behaviour；
- 打开人生页面时重新计算居民过去。
