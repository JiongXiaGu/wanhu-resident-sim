# 居民面板与生活事件 V3

## 目标

Resident Panel 的当前生活信息只保留三个清晰层次：

~~~text
此刻
最近
人生经历
~~~

玩家不需要理解 Action、LifeEvent、Story Thread、Stage 等内部系统名。

---

## 当前生活模式

~~~text
Resident Panel
├─ Identity / Portrait
├─ World Links
├─ 此刻
├─ 最近
└─ 人生经历入口
~~~

### 此刻

只读取真实 `CurrentAction`。

例如：

~~~text
此刻
正在井边打水
~~~

LifeEvent 不覆盖“此刻”。

### 最近

只有一个近期列表。

数据来源可以同时包括：

~~~text
RecentAction
recent LifeEvent
~~~

在展示层按时间从近到远混合。

例如：

~~~text
最近

2日前
去朋友家坐了一阵。

4日前
有人来给家里说亲。
亲友只是先问了问我的意思，我答应找个时间见一面。

7日前
去市上买了些吃用。
~~~

UI 不显示：

~~~text
正在经历
最近发生
Action
LifeEvent
Stage 1 / 2 / 3
~~~

来源差异保留在数据层，不成为玩家的信息分类。

---

## RecentAction 展示

RecentAction 是行为完成事实的短展示。

通常一行或一句即可：

~~~text
3日前 · 家里的水不多了，去井边挑了水回来。
~~~

它不会进入人生经历。

---

## LifeEvent 展示

LifeEvent V3 是一次完整事件。

近期列表可以显示：

~~~text
时间
标题
短正文
~~~

不需要常驻“故事卡”，也不需要等待三个阶段播放完。

LifeEvent 发生后即可进入“最近”。之后是否继续保留、何时淘汰由 Unity 的近期记录策略决定；Content Lab 只验证阅读效果。

---

## 人生经历模式

玩家点击“人生经历”进入独立模式：

~~~text
某某的一生

13岁 · 第一次独自替家里办事      [可展开]
18岁 · 开始做木工
23岁 · 成了家                     [可展开或事实节点]
27岁 · 服役结束回家               [可展开]
31岁 · 家里添了孩子
……
如今
~~~

规则：

- 一条纵向时间轴；
- 按年龄从小到大；
- 不按少年 / 青年 / 壮年分 UI 分组；
- 一个节点只代表一件事；
- Fact Chapter 只显示年龄 + 标题；
- Story Chapter 展开一段 memoryText；
- 末尾保留“如今”。

人生模式隐藏：

- CurrentAction；
- RecentAction；
- 最近 LifeEvent；
- 其它短期生活信息。

---

## “最近”与“人生经历”不是同一份日志

同一个 LifeEvent 可以：

~~~text
发生当天
→ 出现在“最近”

如果足够重要
→ 同时形成 LifeChapter

过一段时间
→ 从“最近”淘汰
→ LifeChapter 长期保留
~~~

普通事件则：

~~~text
发生
→ 最近
→ 自然淘汰
~~~

不会进入人生经历。

---

## 重要结构事实避免重复节点

例如成婚：

如果 LifeEvent “成婚”已经形成一个带 memoryText 的 LifeChapter，同时结构系统又能生成 Fact Chapter，则最终时间轴只能保留一个玩家可见节点。

优先原则：

- 有值得阅读的 memoryText → 使用 Story Chapter；
- 只是结构事实 → 使用 Fact Chapter。

不要出现：

~~~text
23岁 · 成婚
23岁 · 这门亲事定下来了
~~~

两个同义节点。

---

## Content Lab 预览方式

Web 不需要模拟完整城市。

V3 迁移后 Preview Fixture 只需要支持：

- 指定 CurrentAction；
- 注入若干 RecentAction；
- 注入若干离散 LifeEvent；
- 按时间合流“最近”；
- 注入若干 LifeChapter；
- 预览 Tag / 结构事实导致的后续事件资格。

不再需要：

- 推进 Stage；
- 当前 Story Thread；
- Stage 1 / 2 / 3 恢复；
- “正在经历 / 最近发生”切换。
