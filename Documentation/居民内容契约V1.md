# 居民内容契约 V1

## 目标

本文件定义居民内容生产线第一阶段需要稳定下来的三个基础契约：Stable ID、LifeTag、Name V2。

Web Demo 继续用于玩法和内容验证；这些契约则面向后续 Content Compiler、Unity Runtime 与存档兼容。

## Stable ID

所有需要被其它内容引用、进入运行时数据库或写入存档的 Definition，都必须拥有稳定 ID。

示例：

```text
occupation.carpenter
routine.carpenter.tool
lifeevent.service-draft
name.surname.lu
name.given.male.mingyuan
lifetag.served-military
```

规则：

- 使用小写 ASCII。
- 使用 `.` 表达命名空间。
- 单个片段内部可以使用 `-`。
- 显示文本修改不得导致 Stable ID 修改。
- 数组顺序不得作为长期身份。
- Stable ID 在全居民内容域中必须唯一。

当前 Compiler 会把已接入的 Name、LifeTag、Occupation、Routine、LifeEvent 一起注册到全局 Stable ID Registry，并检查格式错误、重复 ID 与 FNV-1a 32 hash 冲突。

生成文件：

```text
Web/public/generated/stable-id-registry.json
```

当前 hash 契约为 `fnv1a32-utf16`。Web 阶段主要用于提前发现冲突；未来 Unity 可以在构建时把 Stable ID 解析成紧凑 RuntimeIndex，但存档层不依赖易变数组下标。

## LifeTag Registry

LifeTag 是居民过去重要经历的紧凑事实，不是玩家成就，也不保存故事正文。

Authoring：

```text
Content/Tags/life-tags.json
```

示例：

```json
{
  "id": "lifetag.served-military",
  "label": "曾经服役",
  "category": "experience"
}
```

第一批标签只建立 Registry，不要求现有 LifeEvent 立即写入这些标签。后续 Story Eligibility / Effect 再逐步引用 `requiredTags`、`forbiddenTags`、`addTags`、`removeTags`。

Runtime 目标仍是把常用标签编译成 bitset 或其它紧凑表示，而不是让每个 Resident 保存字符串数组。

## Name V2

姓名 Authoring 不做任意汉字笛卡尔组合。Given Name 使用已经审核过的完整 token，例如“明远、景和、静和、知微”。

当前 V2 源文件：

```text
Content/Names/surnames-v2.json
Content/Names/given-names-v2.json
```

Surname：

```json
{
  "id": "name.surname.lu",
  "text": "陆",
  "weight": 1
}
```

Given Name：

```json
{
  "id": "name.given.male.mingyuan",
  "text": "明远",
  "gender": "male",
  "weight": 1
}
```

可扩展字段包括 `styles` 与 `generationGroups`。

当前已有 V1 姓名池已经完整镜像到 V2 Authoring；Web ResidentGenerator 暂时继续消费原有 V1 文件，下一步再切到 V2 Compiler 输出，避免一次同时修改过多运行时行为。

生成验证目录：

```text
Web/public/generated/name-catalog-v2.json
```

姓名允许重复，不做全城唯一性检查。家庭规则保持 Household 先生成、子女通常继承家庭姓氏、配偶保留原姓。

## Build 契约

`npm run build-content` 的第一步现在是：

```text
ContentContractCompiler
↓
StoryCompiler
↓
ResidentGenerator
↓
LifeEventCompiler
```

ContentContractCompiler 生成：

```text
stable-id-registry.json
name-catalog-v2.json
life-tags.json
```

GitHub Build 会把 `Web/public/generated/*.json` 整体上传为 `resident-generated-data` Artifact，使数据契约错误可以在进入 Web Build 之前失败。
