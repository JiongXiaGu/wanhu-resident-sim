# 居民头像系统与美术资源规范 V1

## 目标

本规范服务 Web 玩法原型，当前只验证三件事：

1. 同一个居民的视觉身份是否稳定；
2. 连续查看几十个居民时是否容易区分；
3. 未来进入 Unity 后，当前验证过的外观语义能否继续复用。

Web 当前使用分层 SVG 只是验证手段，不代表未来 Unity 必须使用 SVG，也不在这里定义正式 Runtime / Save 结构。

## 核心原则：迁移语义，不迁移 Web 渲染代码

当前稳定层是 `AppearanceDNA`：

```text
faceId
hairId
browId
facialHairId
headwearId
outfitId
skinPaletteId
hairPaletteId
clothingPaletteId
```

Web：

```text
AppearanceDNA
↓
Compatibility Resolver
↓
PortraitRig
↓
Layer Renderer
↓
分层 SVG
```

未来 Unity：

```text
AppearanceDNA
↓
Unity Appearance Resolver
├─ 2D Portrait Sprite / Atlas
└─ 3D Mesh / Hair / Material / Outfit
```

同一个 Stable ID 可以在不同表现层映射到不同资源。不要把 `appearance.hair.tied-01` 理解成“某一张 SVG 文件”；它首先代表一种经过审核的外观语义。

## PortraitRig V2

V1 头像的问题不是随机组合太少，而是所有发型、眉毛、胡须和帽子都假定脸长在固定坐标上。脸型高度和宽度一变化，就会产生悬空、错位和穿插。

V2 不维护 `圆脸 + 胡须A = offset 3` 这类组合表，而是让每一个 Face Preset 提供一套轻量锚点：

```text
centerX
headTop / topY
hairLine
browLine
eyeLine
nose
mouth
chin
faceWidth
jawWidth
earLine
neckTop
shoulderLine
```

当前 Web Authoring 中，每个 `appearance.face.*` 都必须具有 `faceFamily + rig`。

附属层只依赖 Rig：

```text
Hair       → topY + hairlineY + faceWidth
Brow       → browY + faceWidth
FacialHair → mouthY + chinY + jawWidth
Headwear   → topY + faceWidth
Neck       → neckTopY
Outfit     → shoulderY
```

因此新增一个脸型时，只需要给它校准一套 Face Rig；不需要重新逐一适配所有胡须和发型。

### Rig 硬规则

编译与头像实验室会检查：

- `topY < hairlineY < browY < eyeY`；
- `eyeY < noseY < mouthY < chinY`；
- 下巴、脖颈和肩线顺序有效；
- `jawWidth <= faceWidth`；
- 脸部保持在头像安全区内；
- 未成年和女性不会生成不允许的胡须组合。

硬规则失败属于装配错误，不能靠“看起来差不多”放过。

## Compatibility Resolver

物理位置正确以后，仍然可能出现审美上不理想的组合。V2 把它和硬规则分开。

部件可以声明：

```text
preferredFaceFamilies
avoidFaceFamilies
```

例如长须可以偏向 `long / oval / broad`，对 `round` 降低权重。

这不是硬禁止：

```text
preferred → 权重 × 1.35
avoid     → 权重 × 0.30
```

这样随机仍有变化，但明显不协调的组合出现率更低。

当前 Face Family：

```text
oval
round
long
square
broad
```

## Headwear / Hair 遮挡

头饰不能只靠 Z-Order 覆盖头发。每个 Headwear 需要声明：

```text
hairVisibility = full | back-only | hidden
```

当前含义：

- `full`：前后头发都保留，例如无头饰或宽檐笠；
- `back-only`：保留后部轮廓、隐藏前发，适合布巾、小帽、文巾；
- `hidden`：未来用于完全替换顶部发型的头饰。

以后正式美术资源仍应沿用同样的遮挡语义，但具体 Sprite Mask / Mesh / Material 实现由 Unity 决定。

## Portrait Art Kit

美术生产优先做模块化 Portrait Kit，而不是一次画大量完整居民头像。

推荐基础层级：

```text
Background
Back Hair
Body / Outfit
Neck
Face Base
Brow
Front Hair
Facial Hair
Headwear
Age / Detail Overlay
```

### Face Base

Face Base 负责主要脸型与核心五官风格，不建议进一步拆成左右眼、鼻子、嘴、耳朵后任意随机组合。

原因：

- 过度拆分容易生成不协调的人脸；
- 美术难以稳定控制统一风格；
- 小尺寸头像里脸型、发型、胡须和头饰比微小五官差异更重要。

### 画布与锚点

正式手绘资源建议统一源文件：

```text
1024 × 1024
透明背景
人物面朝正前或极轻微三分之二角度
头部中心、发际线、眉线、嘴线、下巴、脖颈、肩线使用统一参考线
```

每一个 Face Base 在交付时同时填写一套 PortraitRig。Hair / Beard / Hat 不再针对具体脸型手工微调，而是围绕对应锚点和安全区制作。

所有部件必须共享同一坐标原点。导出分辨率可以按实际 UI 需求缩小，但源文件不要每个部件单独重新裁切。

### 推荐安全区

```text
头顶：保留头饰空间
左右：保留发型 / 帽檐空间
下方：保留肩部与领口空间
```

头像在 48×48 / 64×64 / 96×96 下仍应优先保持：

- 发型轮廓可读；
- 脸型可辨；
- 胡须 / 头饰可辨；
- 服装身份有弱提示；
- 不依赖细小纹样才能区分人物。

## 配色资源

同一服装不应为了颜色重复导出多张图。

推荐美术额外提供区域 Mask：

```text
R = 主布料
G = 次布料
B = 饰边 / 领口
A = 固有明暗或特殊遮罩
```

Unity 可以通过 Material / Shader 把 `clothingPaletteId` 映射为实际颜色。Web Demo 当前直接使用颜色表，只用于验证配色组合是否足够稳定。

肤色和发色也使用 Palette ID，不把颜色写死进居民身份。

## 年龄表现

年龄变化优先保持核心身份稳定，只改变少量可读特征：

```text
Face Base        尽量保持
Brow             通常保持
Hair Family      可在同家族内变化
Hair Palette     随年龄变化概率提高
Age Overlay      中年 / 老年增加
Facial Hair      按年龄和性别变化
```

目标是让玩家能感觉“同一个人老了”，而不是每个年龄阶段重新随机一张脸。

## 家庭相似度（后续切片）

家庭遗传不需要真实遗传模拟。后续可以只验证少量特征继承：

```text
Face Family
Skin Palette Range
Hair Palette Range
Brow Family
```

子女只继承部分特征，其余继续随机。目标是产生弱相似感，不是建立复杂遗传系统。

## Web 头像实验室 V2

访问：

```text
/?view=portraits
```

当前实验室一次生成 64 个随机样本，并增加装配诊断：

- 性别 / 年龄筛选；
- Face Family 筛选；
- “只看异常”；
- 显示 PortraitRig 锚点；
- 单独开关 Hair / Brow / Beard / Headwear / Outfit；
- 硬错误与兼容提醒计数；
- AppearanceDNA 完整查看；
- 头饰 Hair Visibility 状态；
- 换一批随机样本。

Visual Review 会要求默认 64 个头像全部通过 Rig 硬检查，同时保留兼容提醒作为人工美术检查入口。

## 美术验收标准

第一阶段不要求最终品质，先验证：

1. 默认随机样本没有悬空胡须、眉毛越界、帽子明显悬空等硬装配错误；
2. 64 个样本中绝大多数能在第一眼区分；
3. Headwear 的遮挡不会明显穿过顶部发型；
4. 缩小到居民面板尺寸后仍能区分主要轮廓；
5. 同职业只提供弱身份提示，不让服装完全等于职业；
6. 老人不是简单把头发变白；
7. 部件新增后旧 Stable ID 的语义不随意改变。

## Unity 迁移边界

以后进入 Unity 时重新设计：

- SpriteAtlas / Texture2D / RenderTexture 具体方案；
- 3D Mesh / BlendShape / Material 组织；
- ECS 数据布局；
- 缓存策略；
- Save / RuntimeIndex。

需要从本原型带走的只有：

```text
AppearanceDNA 语义
Stable ID
Face Family / Compatibility 规则
PortraitRig / Attachment 语义
Headwear Occlusion 语义
Palette 语义
美术锚点与层级规范
已经通过试玩验证的组合规则
```

这样 Web 原型不会锁死 Unity 实现，但当前做的美术规则和内容验证也不会白做。
