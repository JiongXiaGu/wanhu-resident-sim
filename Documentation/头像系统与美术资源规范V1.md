# 居民头像系统与美术资源规范 V1

## 目标

本规范服务 Web 玩法原型，当前只验证三件事：

1. 同一个居民的视觉身份是否稳定；
2. 连续查看几十个居民时是否容易区分；
3. 未来进入 Unity 后，当前验证过的外观语义能否继续复用。

Web 当前使用分层 SVG 只是验证手段，不代表未来 Unity 必须使用 SVG，也不在这里定义正式 Runtime / Save 结构。

## 核心原则：迁移语义，不迁移 Web 渲染代码

当前稳定层是 `AppearanceDNA`：

```text
faceId
hairId
browId
facialHairId
headwearId
outfitId
skinPaletteId
hairPaletteId
clothingPaletteId
```

Web：

```text
AppearanceDNA
↓
Portrait Resolver
↓
分层 SVG
```

未来 Unity：

```text
AppearanceDNA
↓
Unity Appearance Resolver
├─ 2D Portrait Sprite / Atlas
└─ 3D Mesh / Hair / Material / Outfit
```

同一个 Stable ID 可以在不同表现层映射到不同资源。不要把 `appearance.hair.tied-01` 理解成“某一张 SVG 文件”；它首先代表一种经过审核的外观语义。

## Portrait Art Kit

美术生产优先做模块化 Portrait Kit，而不是一次画大量完整居民头像。

推荐基础层级：

```text
Background
Back Hair
Body / Outfit
Neck
Face Base
Brow
Front Hair
Facial Hair
Headwear
Age / Detail Overlay
```

### Face Base

Face Base 负责主要脸型与核心五官风格，不建议进一步拆成左右眼、鼻子、嘴、耳朵后任意随机组合。

原因：

- 过度拆分容易生成不协调的人脸；
- 美术难以稳定控制统一风格；
- 小尺寸头像里脸型、发型、胡须和头饰比微小五官差异更重要。

### 画布与锚点

正式手绘资源建议统一源文件：

```text
1024 × 1024
透明背景
人物面朝正前或极轻微三分之二角度
头部中心、眼线、下巴、脖颈、肩线使用固定参考线
```

所有部件必须共享同一坐标原点和安全区。导出分辨率可以按实际 UI 需求缩小，但源文件不要每个部件单独重新裁切。

### 推荐安全区

```text
头顶：保留头饰空间
左右：保留发型 / 帽檐空间
下方：保留肩部与领口空间
```

头像在 48×48 / 64×64 / 96×96 下仍应优先保持：

- 发型轮廓可读；
- 脸型可辨；
- 胡须 / 头饰可辨；
- 服装身份有弱提示；
- 不依赖细小纹样才能区分人物。

## 配色资源

同一服装不应为了颜色重复导出多张图。

推荐美术额外提供区域 Mask：

```text
R = 主布料
G = 次布料
B = 饰边 / 领口
A = 固有明暗或特殊遮罩
```

Unity 可以通过 Material / Shader 把 `clothingPaletteId` 映射为实际颜色。Web Demo 当前直接使用颜色表，只用于验证配色组合是否足够稳定。

肤色和发色也使用 Palette ID，不把颜色写死进居民身份。

## 年龄表现

年龄变化优先保持核心身份稳定，只改变少量可读特征：

```text
Face Base        尽量保持
Brow             通常保持
Hair Family      可在同家族内变化
Hair Palette     随年龄变化概率提高
Age Overlay      中年 / 老年增加
Facial Hair      按年龄和性别变化
```

目标是让玩家能感觉“同一个人老了”，而不是每个年龄阶段重新随机一张脸。

## 家庭相似度（后续切片）

家庭遗传不需要真实遗传模拟。后续可以只验证少量特征继承：

```text
Face Family
Skin Palette Range
Hair Palette Range
Brow Family
```

子女只继承部分特征，其余继续随机。目标是产生弱相似感，不是建立复杂遗传系统。

## Web 头像实验室 V1

访问：

```text
/?view=portraits
```

当前实验室一次生成 64 个随机样本，显示：

- 随机姓名；
- 年龄 / 职业；
- 分层头像；
- AppearanceDNA；
- 唯一组合、脸型、发型、头饰、服装覆盖数量；
- 性别 / 年龄筛选；
- 换一批随机样本。

实验室使用与 Authoring 相同的约束：

```text
Gender
LifeStage
OccupationGroup
Weight
```

因此美术和规则设计可以直接在这里暴露重复、异常组合和缺口。

## 美术验收标准

第一阶段不要求最终品质，先验证：

1. 64 个样本中绝大多数能在第一眼区分；
2. 同批头像不存在明显错误穿插、遮挡或性别 / 年龄冲突；
3. 缩小到居民面板尺寸后仍能区分主要轮廓；
4. 同职业只提供弱身份提示，不让服装完全等于职业；
5. 老人不是简单把头发变白；
6. 部件新增后旧 Stable ID 的语义不随意改变。

## Unity 迁移边界

以后进入 Unity 时重新设计：

- SpriteAtlas / Texture2D / RenderTexture 具体方案；
- 3D Mesh / BlendShape / Material 组织；
- ECS 数据布局；
- 缓存策略；
- Save / RuntimeIndex。

需要从本原型带走的只有：

```text
AppearanceDNA 语义
Stable ID
部件适用规则
Palette 语义
美术锚点与层级规范
已经通过试玩验证的组合规则
```

这样 Web 原型不会锁死 Unity 实现，但当前做的美术规则和内容验证也不会白做。
