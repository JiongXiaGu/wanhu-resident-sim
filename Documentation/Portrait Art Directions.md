# 居民头像：新美术方向研究

## 当前决策入口

`/?view=portrait-art-directions` 是当前美术选型页。旧 `portrait-style-study` 和 `portrait-style-bakeoff` 仅用于历史对照，不再是扩展模板。

本轮目标是选出值得继续投入的画风，不是把旧头像换眼睛、换描边，也不是增加一个正式头像 Runtime。

正式运行规范仍以 `Portrait System.md` 为准；本页只取代旧文档中的实验画风选型入口，不改变 DNA、Stable ID、PortraitFrame、RenderPlan 或正式资产。

## 为什么重新作画

旧正式资产虽然可组合，但大量正面长脸与接近的五官排布削弱了角色身份；发型像脸周围的一圈壳，领口与肩部缺少连续的服装构造。女性与老人尤其容易显得呆板。

旧 Bakeoff 的 ElegantFlat 与 CelCharacter 使用了非常接近的脸轮廓、头发及衣服构造，区别主要是眼白、线宽和少量阴影。更换表现参数不等于建立新的角色设计语言。皇室常常只是普通人的配色、头饰变体，老人主要靠灰发与皱纹表达。部分实验还把额前头发画在 Face 之前，随后被脸覆盖。

层序错误是局部缺陷；重复的比例、结构和身份表达则是方向问题。本轮不修历史路径，直接独立作画。

## 三组候选

| 方向 | 造型与表现 | 适合之处 | 需要取舍 |
| --- | --- | --- | --- |
| 绢彩小像 | 较自然比例、完整眼睑、弧线发束、温润肤色与细线衣料层次 | 生活叙事与贵族角色之间跨度较宽 | 小尺寸损失细线，正式版需要降低细节密度 |
| 暖陶绘本 | 更大的头部、饱满面颊、短下庭、点面五官、无外描边 | 平民、儿童和轻松的居民互动 | 皇室威严较弱，量产时不能人人固定微笑 |
| 朱墨刻绘 | 不对称构图、折线骨点、留白塑形、朱墨套色 | 强剪影、角色辨识和鲜明的视觉个性 | 更硬朗，表情细腻度较低；不是写实或古画复刻 |

每组分别绘制平民女性、平民男性、老年居民、儿童、贵族女性与皇帝/高阶男性，共 18 个角色稿。比较的是相同角色类别，不是假定同一个人换滤镜；例如绢彩的老人是女性，另两组是男性，因此这一轮不能用来证明跨画风身份保真。

身份差异通过发髻体量、冠服、肩部轮廓、领口层次、衣料明暗与礼服纹样表达。面部不承担夸张的民族特征编码。衣服只是角色研究设定，没有改动职业/财富的运行选择逻辑。

## 源码与隔离

```text
Web/src/portrait-art-directions/
  PortraitArtDirections.tsx  页面、筛选、背景、近景及导出
  directions.css            仅以 pad- 为作用域的页面样式
  catalog.ts                候选方向与角色研究说明
  art/svg.ts                SVG 基元与类型，不包含人物几何
  art/silk.ts               绢彩：独立角色几何
  art/clay.ts               暖陶：独立角色几何
  art/ink.ts                朱墨：独立角色几何
```

三个方向不导入旧 Style Study、Bakeoff 或正式 `resident/portrait`，也不共用脸、五官、发型、衣服模板。相同的绘图基元只是 path、ellipse 等序列化，不是换皮生成器。

角色稿是自包含的透明底 256×256 SVG。SVG 通过独立 `img` 图像文档显示，不往页面注入 SVG 字符串，避免渐变 ID 冲突。研究页面按 route 懒加载，正式居民界面不加载这些新资产。

本轮没有实现随机换装，也没有增加生产角色 ID。几何在角色研究文件里保持完整；只有入选以后才拆生产层。

## 评审页面

页面提供三个方向并排阅读、单方向筛选、纸白/暮色画布、角色近景、实际 96/64/48 CSS px 样本，以及单张 SVG 导出。

背景按钮只改变画布，不能用改色滤镜伪装另一套角色。小尺寸样本不能随容器缩放。浏览器缩放和屏幕 DPR 仍会影响物理像素，所以自动审查统一使用 DPR 1，并断言每张图的实际 CSS 边长。

夜间画布使用中等明度的蓝灰衬底，使墨色头发和冠帽仍然有完整轮廓。研究稿不保证直接叠在任意近黑背景上都可读；生产时需要统一头像底色，而不是用动态滤镜修改角色。

近景对话框支持键盘打开、Escape 关闭、焦点返回和 SVG 下载。页面适配桌面与 390px 宽度。

## GitHub Actions 验收

沿用 **Build + Resident Visual Review**。不使用 Vercel、Preview、Production 或公网部署。

`capture-art-directions.mjs` 在现有居民玩法/正式头像回归之后运行，检查：

- 3 组 × 6 个不同角色、18 份不同 SVG，且不导入正式或旧实验资产；
- 筛选、背景切换、近景键盘交互、焦点恢复、单张 SVG 下载；
- 全部 54 张 96/64/48 CSS px 样本的真实边长；
- 桌面与 390px 页面无横向溢出，浏览器无 JS、console 或 HTTP 错误；
- 导出 18 张透明底研究稿 SVG 与 PNG，作为资源形式验证，不声称已通过 Unity 导入。

新增文件位于 `resident-visual-review` Artifact 的 `art-directions/` 下：

```text
80-all-directions-paper.png           三组总览
81-{silk,clay,ink}-paper.png           各组角色稿
82-{silk,clay,ink}-night.png           暮色画布
83-*-detail.png                       平民女性和贵族女性近景
84-*-actual-pixels.png                真实尺寸检查
85-all-actual-pixels-night.png        暮色小尺寸检查
86-*.png / 87-*.png                   移动端与对话框
study-exports/                       18 份 SVG + 18 份透明 PNG
review.json                          自动断言结果与本次 commit
```

这些原始 PNG 位于子目录，不经过旧顶层截图脚本的有损缩图和删除步骤。不要把压缩预览当作实际像素判据。

**自动通过不等于画风获批。** 每轮仍须下载并实际查看图片。合入 main 只表示新的候选研究页和回归可验收，不表示已经替用户选定正式画风。

## 进入生产前的下一道门槛

先由用户选择一个或两个值得推进的方向，再验证：

1. 同一张脸换三个发型、四套衣服，组合后无漂移、不牺牲美术。
2. 同一 FaceFamily 的 child/adult/elder 有辨识连续性，再覆盖六个 Frame。
3. 普通居民、老人和皇室都在同一个美术世界；至少补另一性别老人。
4. 48/64/96px 及 24–64 人群体检查，不能只靠重复六张图证明多样性。
5. 固定裁切、层序、调色语义和衣领遮挡成立以后，才回到正式资产体系。

Unity 可以评估栅格化 Sprite 或分层贴图；可导出 SVG/PNG 仅证明资源可交付，不证明引擎渲染、图集、性能、换装或大规模居民已经验证。不要为这些研究稿添加 Anchor、Mask、Offset Solver、兼容图或新存档字段。

原则：先把人画好，再证明能够量产；不要反过来用运行时代码替美术补洞。
