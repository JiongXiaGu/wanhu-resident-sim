# 居民事实事件、最近行为与人生记录语义设计

## 目标

本文件只记录 Unity 主工程未来需要保持的语义边界，不规定具体 ECS、事件容器、调度算法或 Save 物理布局。

~~~text
Behaviour
→ CurrentAction
→ Completed Action
→ RecentAction

LifeEvent Trigger
→ 离散 LifeEvent
→ Effects / Tag / 结构事实
→ optional LifeChapter
~~~

Resident Content Lab 只用固定 Fixture 预览这些语义。

## CurrentAction

玩家“此刻”只来自真实 Behaviour。

LifeEvent 不在 UI 层覆盖 CurrentAction。

如果事件应影响行为，由 Unity 的 Schedule / Utility / Story Action Request 改变真实 Behaviour。

## RecentAction

RecentAction 只记录值得展示的完成行为。

记录系统不重新推断职业、家庭、财富、天气或目标关系。

## LifeEvent

LifeEvent V3 是一次完整发生的离散事件。

它发生时可以：

- 显示在“最近”；
- 写入 / 移除 LifeTag；
- 发出结构变化请求；
- 如果足够重要，形成 LifeChapter。

不要求居民长期保存 Story Thread、Stage、NextStageDay。

长故事由多个独立 LifeEvent 组成。

## 连续性

优先级：

~~~text
真实结构状态
>
长期 LifeTag
>
短期机会 Tag
~~~

结构状态能表达的事实不重复写 Tag。

长期 LifeTag 用于已经结束但多年后仍可能影响内容的经历，例如曾经服役。

短期机会 Tag 用于一小段后续候选，例如 newly-married。

禁止使用 stage-1 / stage-2 / stage-3 Tag 重建状态机。

## 最近 UI

数据层可以继续区分：

~~~text
RecentAction
LifeEvent
~~~

玩家 UI 只显示一个“最近”，按时间混合排序。

这只是展示合流，不要求 Unity 把两类记录存成同一种 Buffer。

## LifeChapter

长期历史只在两类时刻产生：

1. 结构事实值得长期回看；
2. LifeEvent 明确 `recordToHistory`。

Fact Chapter 通常只有年龄 + 标题。

Story Chapter 可以通过 Event ID 回查 `memoryText`。

同一件结构变化不生成两个同义 Chapter。

## 保存边界

正式 Save 可以根据 Unity 需要保存近期小环和 LifeChapter，但不保存展示文本。

不再以 StoryThread / Stage 作为长期存档契约。

## Content Lab 边界

当前 Web main 仍有 V2 Stage Fixture。下一代码批次迁移后，Preview 只需支持：

- CurrentAction；
- RecentAction；
- 离散 recent LifeEvent；
- LifeChapter；
- 结构事实 / Tag 后续资格。

Web 不实现正式 Trigger、Utility、Behaviour 或 Save。
