# 居民事实事件、日常记录与人生经历运行时设计

## 文本契约

当前结构已经可以作为 Unity 上层稳定契约：

- Routine：一句短文本，只保留近期窗口，不进入人生经历。
- LifeEvent：固定三段 Stage，每段包含 delayDays、title、text，可选 activityOverride，用于生活模式。
- Life Chapter：一个节点只代表一件事。事实章节显示年龄/日期与标题；重要故事章节通过 sourceEventId 找到一段第一人称 memoryText。
- memoryText 不拼接三个 Stage，也不显示“起初 / 后来 / 最后”。

后续可以增加 Stage / memoryText 文本变体，但不改变“近期日常 / 三段进行中故事 / 单节点人生回忆”三层结构。

## ECS Job 只产出事实

行为树、Schedule、Utility 等高频 Job 不拼字符串、不查本地化、不直接维护 UI 日志，也不要每经过一个行为树节点就记录一次。

只在有意义的行为完成点写紧凑 ResidentFactEvent，例如上工完成、买到东西并离开市场、回家、完成交谈、送货完成、收工、到达故事地点、婚姻/搬家/换工作/添孩子真正落地。

建议 Fact 只包含 ResidentId、FactTypeId(RuntimeIndex/hash)、Day/Tick、可选 TargetEntityId、PlaceId、ItemOrServiceId、Value 与 Flags。

推荐链路：行为 Jobs → ResidentFactEventStream → ResidentLifeRecordSystem → 去重/冷却 → Routine Resolver / LifeEvent Trigger / LifeChapter Request。

事件流优先使用 NativeStream，或预分配 NativeList/NativeQueue ParallelWriter；固定容量允许超量丢弃并统计。不要为了日志创建大量临时 Entity。

## 日常如何触发

不要每天给所有居民生成日记。应该由真实完成的行为事实触发，再经过记录策略筛选。

例如木工磨完工具：SharpenTool 完成 → fact.work.tool-maintenance。记录系统检查十天内没有同类记录、近期没有连续同模板，再映射到 routine.carpenter.tool。

RecentLifeLog 推荐 8~12 条小环形记录，只保存 Day、RoutineId/FactPresentationId、VariantIndex 和必要 ContextIds。超出时间或容量自然淘汰。

## LifeEvent 如何接 Job

LifeEvent Trigger 读取居民当前事实、年龄性别、职业家庭、LifeTag、最近 Fact、城市状态，以及当前是否已有互斥 Story Thread。选中 Definition 后只保存 EventId、StartDay、CurrentStage、NextStageDay 和必要 ContextIds。

Stage 到期按内容定义推进。只有 activityOverride 临时影响当前行为；故事结束后覆盖消失。

## 人生记录

长期历史只在两类时刻写入：

1. 结构事实真正成功：开始/换工作、成婚、添孩子、搬家等，写 Fact Chapter，不需要文学正文。
2. LifeEvent 完成且 recordToHistory 为 true，或带长期 structural effect，写一个 Story Chapter，只保存 SourceEventId 和必要 ContextIds。

人生页通过 SourceEventId 找 memoryText。以后若有 memoryText 变体，只增加稳定 VariantIndex，不复制 Stage 原文。

LifeTag 负责系统连续性：过去影响未来只读少量标签，不扫描历史文本。

## 保存边界

长期保存居民稳定身份与个人资料、当前 LifeEvent、Major Life History、长期 LifeTag、必要的近期 Routine、玩家头像覆盖。不要保存行为树临时节点、每帧 Fact Stream、可由内容 ID 重建的显示字符串或完整行为轨迹。
