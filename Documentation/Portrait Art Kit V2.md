# Portrait Art Kit V2

## 目标

V2 将居民头像从“程序组合原型”推进到可持续制作正式游戏头像资产的阶段。

本阶段的核心不是继续增加随机部件数量，而是解决三个基础问题：

1. 男性与女性不能只依赖“短发 / 长发、胡须 / 无胡须”区分。
2. 财富差异要由衣领、叠层、肩颈完整度和细节精度表达，而不是职业制服。
3. 每次改美术后必须自动生成视觉审查图，由实际组合结果决定是否通过，而不是只依赖代码与 Rig 校验。

Web 版本仍然是美术与玩法语义原型。最终 Unity 资源可以重画或转成正式矢量 / 纹理资产，但稳定的 Appearance ID、4:5 母版、1:1 Safe Area、分层顺序和组合语义应继续保留。

---

## V2 美术方向

风格继续使用：

- 扁平古风；
- 轻纸片 / 拼贴感；
- 低饱和暖色；
- 近正面胸像；
- 不写实；
- 不做 Q 版；
- 不使用职业制服作为居民身份主提示；
- 不使用现代网红脸式女性化表达。

人物首先应当像“不同的人”，其次才通过年龄、财富、发型和饰品增加生活状态信息。

---

## 背景规范

V2 头像背景改为干净的纯色底。

禁止：

- 头像头部后方圆形光环；
- 放射状亮斑；
- 模拟聚光灯的圆形渐变；
- 会被误认为人物轮廓一部分的背景装饰。

当前 Web 原型使用单一深灰绿色背景 `#33413b`。

Renderer 必须暴露：

- `data-background-style="clean-flat"`
- `data-halo="none"`

视觉 CI 会校验这两个契约。

---

## 母版与裁切

继续沿用 V1 已确定的尺寸：

- 美术母版：4:5；
- 参考尺寸：1024 × 1280；
- Web Rig：120 × 150；
- 1:1 Safe Area：1024 × 1024；
- Web Safe Area：`x=0, y=15, w=120, h=120`。

居民列表和绝大多数游戏 UI 使用 1:1 裁切。

必须留在 Safe Area 内：

- 主脸；
- 眼、眉、鼻、口；
- 主要发型识别信息；
- 胡须主体；
- 主要衣领。

允许少量超出 Safe Area：

- 发髻顶部；
- 发簪末端；
- 长发末端；
- 小范围肩部延伸。

## Face Base V2

### 原则

V1 的主要问题是不同 Face ID 最终仍大量共享同一套图形语言，尤其男性与女性差异主要来自头发和胡须。

V2 将 Face Base 拆成独立美术配置：

`Web/src/resident/portrait-art-v2.ts`

每个 Face ID 可以拥有自己的：

- 脸部整体比例；
- 太阳穴收放；
- 颧颊宽度；
- 下颌比例；
- 下巴深度；
- 眼距；
- 眼宽；
- 眼线弧度；
- 眉毛粗细；
- 鼻长与鼻宽；
- 嘴部宽度与弧度；
- 耳部比例；
- 颈部比例；
- 肩部比例；
- 轻微面颊结构线。

这些参数是“矢量美术配置”，不是居民身体模拟参数。

### 性别差异

女性 Face Base 当前主要通过以下组合形成辨识：

- 略小且更有变化的下颌；
- 更清晰的眼部比例差异；
- 更柔和的眉线；
- 鼻口尺度差异；
- 更窄的颈肩关系；
- 不同的面颊和下巴节奏。

男性 Face Base 当前主要通过以下组合形成辨识：

- 更稳定的颌面体积；
- 更平直或更厚的眉眼节奏；
- 更明确的鼻部体积；
- 更宽的颈肩关系；
- 方脸、宽脸、长脸之间更明显的轮廓区别。

胡须不是男性识别的必要条件；长发也不是女性识别的必要条件。

### 验收方法

必须有一张 Face Base 审查图：

- 关闭 Back Hair；
- 关闭 Front Hair；
- 关闭 Facial Hair；
- 关闭 Headwear；
- 男女样本并排显示。

如果关闭这些层后，男女仍像同一套脸换少量参数，则本轮 Face Base 不通过。

## Hair V2

Hair 继续分为：

1. Back Hair
2. Front Hair

女性长发、辫发和低髻必须通过 Back Hair 改变整体人物外轮廓，而不是只在额头上换一个发片。

Front Hair 主要负责：

- 发际线；
- 中分 / 偏分；
- 脸侧落发；
- 与五官的局部遮挡。

Back Hair 主要负责：

- 长度；
- 辫子；
- 发髻；
- 耳后和肩部外轮廓。

`silhouetteType` 继续作为同屏去重的稳定语义。

---

## Outfit V2

服装按 Household Wealth / Presentation 表达生活状态，不绑定职业。

### 贫寒 poor

- 单层；
- 领口简单；
- 边线不完全对称；
- 细节少；
- 肩线更松散。

### 普通 plain

- 基础交领；
- 结构完整；
- 装饰少。

### 殷实 comfortable

- 双层或厚领；
- 肩颈结构更完整；
- 有少量内领 / 肩缝细节。

### 富裕 wealthy

- 多层领口；
- 更清楚的滚边；
- 少量精致扣饰或横向层次；
- 仍然保持低饱和与日常感。

富裕不等于高亮、高饱和、金色大面积装饰。

---

## 分层顺序

正式顺序继续是：

1. Background
2. Back Hair
3. Body / Outfit
4. Neck
5. Face Base
6. Brow / Face Detail
7. Front Hair
8. Facial Hair
9. Headwear / Accessory
10. Age Overlay

Rig Debug 不属于正式美术层。

## Visual QA V2

新增脚本：

`scripts/capture-portrait-art-v2-review.mjs`

Resident Visual Review CI 会在原有居民回归检查之后执行 V2 美术审查。

固定输出：

- `11-portrait-v2-batch`：64 人整体组合；
- `12-portrait-v2-women`：女性样本；
- `13-portrait-v2-face-base`：关闭头发 / 胡须 / 头饰后的男女 Face Base；
- `14-portrait-v2-golden`：固定 Showcase / Golden 候选；
- `15-portrait-v2-wealth`：四档财富并排；
- `16-portrait-v2-size-review`：48 / 64 / 96px 实际 1:1 使用尺寸。

这些截图是正式美术迭代的一部分，不是单纯 CI 附件。

## 审查顺序

每轮头像修改按以下顺序判断：

### 1. 结构检查

自动判断：

- 4:5 Master 是否存在；
- 1:1 Safe Area 是否保持；
- Rig 是否越界；
- 女性是否错误生成胡须；
- 资源性别 / 年龄规则是否冲突；
- `silhouetteType` 是否缺失；
- 背景光环是否被重新引入。

### 2. Face Base 检查

人工看 `13-portrait-v2-face-base`：

- 男女是否仍然过于同源；
- 各个脸是否只是宽窄变化；
- 青年 / 成年 / 中老年是否有合理变化；
- 是否出现现代审美模板脸。

### 3. 组合检查

人工看 64 人总览：

- 是否有明显“同一个人换头发”；
- 发型是否像贴纸；
- 胡须与脸是否脱节；
- 头饰是否悬浮；
- 衣领与脖颈是否错位；
- 某个合法组合是否实际不可用。

### 4. 财富检查

人工看财富 Contact Sheet：

- 贫寒是否足够简单；
- 普通是否不显破旧；
- 殷实是否比普通更完整；
- 富裕是否更讲究但没有制服化、页游化。

### 5. 小尺寸检查

人工看 48 / 64 / 96px：

- 眼眉是否糊成噪点；
- 男女与年龄是否仍能读出；
- 主要发型轮廓是否成立；
- 财富衣领在 48px 不要求读出全部细节，但不能形成脏线。

## 美术结果等级

### Reject

存在明显不可用于游戏的组合或基础美术问题。

常见原因：

- 男女高度同脸；
- 轮廓重复；
- 头发贴片感明显；
- 衣领错位；
- 小尺寸脏乱；
- 合法随机组合明显丑。

### Prototype Approved

结构和方向已经成立，但仍需要扩充 / 精修资产。

### Game Asset Approved

这一批组合即使直接出现在居民 UI 中，也达到当前项目可接受的正式头像质量。

后续美术迭代应以 Game Asset Approved 为目标。

---

## 后续资产生产流程

1. 修改或新增 Face / Hair / Outfit / Accessory 美术定义。
2. 运行 Build。
3. 运行 Resident Visual Review。
4. 读取 V2 审查截图。
5. 标记 Reject 组合与具体原因。
6. 优先修改资产；只有确实属于组合冲突时才增加 Resolver 降权 / 禁止关系。
7. 重新生成审查图。
8. 直到 Golden、随机组合和小尺寸同时通过。

原则：不能为了让一张 Golden Portrait 好看而破坏真实随机居民的稳定性。
