# 故事写作规范

## 目标

居民故事要像普通人的生活片段，而不是固定三幕小说。

新的 LifeEvent 基本单位是：

> 一次完整、离散、可以单独读懂的事情。

多个事件之间可以通过结构事实与 LifeTag 产生弱连续性。

## 叙事视角

- 默认第一人称。
- 不需要反复介绍居民姓名。
- 少对话，多用动作、物件、地点和结果推进。
- 角色只能知道自己合理能够知道的信息。
- 避免旁白替角色总结人生道理。

## 单个 LifeEvent

推荐正文：

- 约 35～80 个中文字符；
- 1～3 个短句；
- 一次读完能知道发生了什么；
- 至少包含一个具体动作、对象、地点或生活细节；
- 不要求再写“过几天怎样 / 最后怎样”。

例如：

~~~text
有人来给家里说亲

姨母今日来问我的意思，说城南有户人家想先见一面。我没有立刻答应亲事，只说可以找个空闲时候去茶铺坐坐。
~~~

这已经是一条完整 LifeEvent。

## 不再强制三阶段

停止把所有故事写成：

~~~text
Stage 1
→ Stage 2
→ Stage 3
~~~

如果旧三阶段其实只是同一件小事，应压缩成一个 LifeEvent。

如果三个节点各自具有独立意义，应拆成多个 LifeEvent。

例如：

~~~text
有人来说亲
→ 两家谈妥
→ 成婚
→ 新婚后的生活
~~~

它们分别可以发生在不同时间，并允许中间出现其它事件。

## 弱关联故事组

连续性来自事实和 Tag，而不是固定下一幕。

例如：

~~~text
服役结束回家
→ lifetag.served-military

多年后
→ 旧同伍进城
~~~

或者：

~~~text
成婚
→ spouse 真实结构变化
→ lifetag.newly-married

之后
→ 多个“新婚生活”候选事件都可以获得资格
~~~

不要要求某个 Tag 只能指向唯一下一条故事。

## Tag 写作规则

优先级：

~~~text
真实结构状态 > 长期 LifeTag > 短期机会 Tag
~~~

不要用 Tag 重复已有结构事实。

不要创建：

~~~text
story-stage-1
story-stage-2
story-stage-3
~~~

不要把 LifeTag 当成隐藏版 Story Thread。

## 进入人生经历的事件

值得进入 LifeChapter 的事件，应额外提供 `memoryText`。

memoryText：

- 第一人称；
- 约 80～180 个中文字符；
- 是多年后回看的一整段记忆；
- 不重复 UI 系统词；
- 不按“起初 / 后来 / 最后”机械分段；
- 只保留真正值得记住的细节。

普通邻里、天气、短期忙碌等事件不需要 memoryText。

## 时间

离散 LifeEvent 本身只需要一个发生时间。

如果后续事件需要等待：

- 时间间隔由 Unity 触发规则、冷却或 Tag / 状态条件决定；
- Authoring 可以表达语义上的合理时间窗口，但不写固定 Stage 延迟链；
- 明确锚点优先，例如生产周期、节令、孩子年龄、服役期限。

## 内容平衡

持续覆盖：

- 邻里；
- 婚嫁与家庭；
- 债务与生计；
- 学业 / 学徒；
- 女性营生；
- 生育与育儿；
- 儿童成长；
- 疾病 / 求医；
- 娱乐 / 节庆 / 庙会；
- 合作与互助；
- 少量民俗 / 悬疑；
- 城市设施变化；
- 晚年；
- 正向发展。

避免所有重要事件都围绕婚嫁、死亡、欠债和冲突。

普通幸福、改善、熟悉的日常变化同样重要。
