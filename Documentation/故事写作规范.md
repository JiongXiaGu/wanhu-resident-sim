# 故事写作规范

## 目标

居民内容分成两种完全不同的写作密度：

~~~text
最近
→ 一句短记录

人生经历
→ 一段完整回忆
~~~

不要再写一种“中等长度 LifeEvent 正文”同时服务两个界面。

## 近期短句 recentText

`recentText` 用于“最近”。

目标是让玩家快速了解居民最近在做什么或遇到什么。

规则：

- 一句话；
- 通常约 12～36 个中文字符；
- 第一人称或自然的居民行动表达；
- 尽量包含具体动作 / 对象 / 地点之一；
- 不铺陈背景；
- 不解释前因后果；
- 不总结；
- 不使用标题 + 正文结构。

例如：

~~~text
去朋友家坐了一阵。
有人来给家里说亲。
孩子第一天进了私塾。
和城南张家姑娘成了婚。
旧同伍进城来看我。
~~~

如果内容本质上就是一个真实 Behaviour，优先补 Action Presentation，不要重复造 LifeEvent。

## 人生故事 memoryText

只有值得进入 Story Chapter 的事件才写 `memoryText`。

规则：

- 第一人称；
- 约 80～180 个中文字符；
- 多年后回看仍值得记住；
- 保留具体人物、动作、地点、物件或生活细节；
- 可以交代过程和结果；
- 不写系统词；
- 不按 Stage 1 / 2 / 3；
- 不机械使用“起初 / 后来 / 最后”；
- 不总结人生大道理。

例如同一个成婚事件：

~~~text
recentText
和城南张家姑娘成了婚。

memoryText
那阵子姨母替我牵了线，我们在茶铺见过几回……
~~~

短句和长故事必须分别写，不能把 memoryText 截断后直接当 recentText。

## title

`title` 主要服务：

- Authoring 识别；
- LifeChapter 时间轴标题；
- DEV / Review。

普通“最近”列表不显示 title。

标题应概括一件人生事件：

~~~text
第一次独自替家里办事
服役结束回家
今日成了婚
第一次独自接下一户出诊
~~~

## 离散事件

LifeEvent 仍是一件完整、离散的事情，不回到三阶段。

停止：

~~~text
Stage 1
→ Stage 2
→ Stage 3
~~~

如果多个节点分别有意义，拆成多个事件，通过事实或 Tag 弱关联。

## 弱关联故事组

连续性来自：

~~~text
真实结构事实
>
长期 LifeTag
>
短期机会 Tag
~~~

例如：

~~~text
服役结束回家
→ served-military

多年后
→ 旧同伍进城
~~~

或者：

~~~text
成婚
→ spouse
→ newly-married

之后
→ 多个新婚生活候选获得资格
~~~

不要要求某个 Tag 只能指向唯一下一条故事。

不要创建：

~~~text
story-stage-1
story-stage-2
story-stage-3
~~~

## 哪些内容进入人生经历

值得写 memoryText 的通常是：

- 成婚 / 丧偶；
- 添孩子或重要育儿节点；
- 服役；
- 迁居；
- 开铺；
- 学成一门手艺；
- 第一次承担重要责任；
- 重大的职业变化；
- 长期疾病 / 恢复；
- 晚年生活方式发生明显改变；
- 对人生方向有持续影响的合作、损失或转折。

通常不写 memoryText：

- 普通买粮；
- 一次散步；
- 一次串门；
- 一次小雨耽误做活；
- 普通邻里互助；
- 很快恢复原状的小事。

这些内容如果值得展示，只需要 recentText。

## 时间

离散事件本身只有发生时间。

如果后续故事需要等待：

- 由 Unity 的事件候选 / 冷却 / 世界条件控制；
- Tag / 结构事实只提供资格；
- 明确的节令、年龄、生产周期等锚点优先；
- 不恢复固定 Stage 延迟链。

## 内容平衡

Life History 重点覆盖：

- 家庭与婚嫁；
- 职业成长；
- 学业 / 学徒；
- 女性营生；
- 生育与育儿；
- 儿童成长；
- 疾病 / 求医；
- 迁居；
- 债务与生计；
- 服役；
- 合作与互助；
- 晚年；
- 正向发展；
- 少量民俗 / 悬疑。

不要把每个居民写成连续遭遇重大剧情的主角。

普通人的人生可以长期平稳，故事密度允许很低。
