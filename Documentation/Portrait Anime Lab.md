# 二次元头像与表情实验

## 定位与入口

`/?view=portrait-anime-lab` 是独立的赛璐璐风格实验。原来的 16 脸 DIY、完整角色研究与正式居民头像继续保留，不覆盖资产，不更改正式五字段 DNA、六个 PortraitFrame、居民 Snapshot 或游戏情绪逻辑。

本轮不是把旧脸放大眼睛，也不是为八种表情各画一张绑定服装的整图。新美术在固定正面画布上分层：不同的脸共享发型、帽饰、衣装，同一张脸独立选择表情。

## 当前范围

- 成年女性四张脸、成年男性四张脸，共八个面容资产。
- 八种预设表情：平静、微笑、开心、大笑、生气、委屈、惊讶、害羞。
- 每个成年 Frame 四个发型：挽髻、高束、编发、半束。
- 无帽饰、布巾、束发冠、斗笠，共四个选项。
- 交领常服、市井外搭、圆领袍服、锦衣礼服，共四套衣服。
- 四种肤色、三种发色、四组服装配色。
- 配方本地保存、JSON 导入/导出、包含表情的分享链接，以及透明 SVG / 512px PNG 导出。

“自定义表情”在当前版本中指玩家选择并保存八套协调表情之一，不是自由拖拽五官或任意拼接眼鼻嘴。不会把随机组合出的失调五官当作表情数量。

## 美术规则

新方案采用较大的虹膜、明确的上眼线、小面积赛璐璐阴影和清晰发束。中国古代语境来自挽束发、交领/圆领、布巾/发冠/斗笠，不靠面部族群刻板特征，也不套用现代校园服装。

头像保持正面。鼻子、嘴和下颌服从中线，微笑两端同高；闭口笑、露齿笑、闭眼大笑分别制作。嘴部的几何对称是防止歪嘴的底线，不等于审美已经通过。

每个 FaceFamily 有独立轮廓和眼型设计。表情以这一眼型为基础选择不同眉、眼、口的协调绘法，不能把一张万能眼睛贴给全部人物。虹膜配色属于面容设计，切换表情不会改变。

四脸设计区分包括面颊、下颌、脸长感、眼型宽高、眼尾和嘴型尺度；男女分别绘制，不把同一轮廓换发型充作两个 Frame。

## 数据与分层边界

源码：`Web/src/portrait-anime-lab/`。

```text
model.ts                 实验配方、选项白名单、保存与种子随机
art/drawing.ts           新配色、SVG 基元、虹膜色阶
art/faces.ts             八个轮廓与各自的眼型设计、固定颈部
art/expressions.ts       八套协调表情、居中嘴型
art/hair.ts              新的发束与发髻、收发状态
art/wardrobe.ts          新衣装与帽饰
render.ts                固定渲染顺序与透明导出
PortraitAnimeLab.tsx     DIY 与对照页
anime.css                仅 pa-* 范围的样式
```

配方使用独立标识：

```text
schema: wanhu.anime-portrait
version: 1
frame
face
expression
hair
hat
outfit
skin
hairColor
cloth
```

本地保存键是 `wanhu.portrait-anime.v1`，与原版 Composer 分开。只接受当前白名单和完整字段；最大导入 8 KB。旧 Composer 配方会明确拒绝，不悄悄转换或覆盖旧存储。

绘制顺序：

```text
BackHeadwear → BackHair → HairCrown → Neck → Outfit
→ FaceBase → Expression → FrontHair → FrontHeadwear
```

画布固定为 `0 0 256 256`。两侧眼眉使用固定 `translate(256 0) scale(-1 1)` 镜像完成对称作画；这不是根据脸型求解偏移、缩放或适配。没有每脸偏移表、Mask、ClipPath 或自动对齐器。

正式五层 RenderPlan 完全不变。这个实验的 `Expression` 层和画布不是正式 Runtime 合同；不可据此重构生产头像。

## 三项不变量

```text
换衣装 / 发型 / 帽饰 → FaceBase、Expression 不变
换表情 → FaceBase、衣装和头发不变
换面容 → 衣装和头发不变；改用该脸自己的五官设计
```

布巾和斗笠使用收发状态：不改变保存的发型 ID，只暂收顶部发髻，摘帽恢复原 SVG。束发冠允许露发。帽檐可能遮住部分眉额，这是正常遮挡，不保证戴帽时八种表情同样容易辨认。

“保留面容与表情”随机搭配同时保留肤色和成年 Frame。取消锁定后，当前 Frame 内完整目录随机。它只是样本工具，不代表人口生成权重。

## 对照与验收

用户可直接查看同脸八表情、相同衣装下的四张脸、共享发型、帽饰、服装和发型×帽饰矩阵。面容与表情对照保留 96/64/48 CSS px 的实际尺寸，不放大补偿。

新增 `scripts/capture-anime-review.mjs`，接在原有 Resident Visual Review 后面；不移除居民生活链、正式头像或原 Composer 的任何检查。

自动检查：

- 2 Frame × 4 Face × 8 Expression × 4 Hair × 4 Hat × 4 Outfit = 4,096 个基础配方的图层独立性与合法 SVG。
- 64 个嘴型的实际 SVG bbox 中点为 x=128，并进行左右镜像栅格差异检查。
- 每张脸都有八表情截图，64 份组合 SVG/PNG；每脸 16 个发型帽饰样本，共 128 个；每脸四套衣服，共 32 个。
- 全部原尺寸样本、白天/暮色、深肤/银发、390px 和 320px 布局。
- 真正点击和键盘切换表情、摘帽恢复、锁脸随机、导出下载、有效/无效配方导入、刷新恢复和分享链接编辑。
- 独立 512 种子目录覆盖；对旧 Composer 存储键设置哨兵，确认未改写。

原始截图在 `resident-visual-review` Artifact 的 `anime/` 子目录，不经过旧的缩图压缩。`exports/` 是渲染器输出的 64 份组合样本，不是运行时读取的固定角色图片。

CI PASS、参数数量、居中检测和栅格对称都不能代替人工审美。必须下载并打开面容总览、八表情矩阵、嘴部、发型帽饰、服装、小尺寸、夜间和移动端截图，发现问题先修正，再推进 main。

## 未完成事项

当前没有儿童/老人、自由五官编辑、游戏状态驱动的自动情绪、动态口型或 Unity 引擎导入。没有把八套表情宣传为已覆盖全部情感，也没有证明所有小尺寸表情同样容易区分。先让玩家对比两套画风，再决定正式方向和后续资源量产。
