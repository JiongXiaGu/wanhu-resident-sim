# 居民生活记录与故事连续性

## 目标

居民系统只保留三个玩家时间尺度：

~~~text
此刻
最近
人生经历
~~~

它们回答不同问题：

~~~text
此刻       这个人现在正在做什么
最近       这个人最近做过什么 / 遇到过什么
人生经历   这个人为什么会成为今天这个人
~~~

三者不能承担同一种叙事密度。

---

## 三层关系

~~~text
Resident
├─ CurrentAction
│  └─ 此刻
├─ Recent
│  ├─ RecentAction
│  └─ RecentLifeEvent
│      └─ 一句 recentText / Presentation
└─ LifeChapter
   ├─ Fact Chapter
   └─ Story Chapter
       └─ memoryText
~~~

- `CurrentAction`：真实 Behaviour 当前状态。
- `RecentAction`：真实 Behaviour 完成后的近期记录。
- `RecentLifeEvent`：非普通 Behaviour 的近期事件事实，但展示时同样只是一句短记录。
- `LifeChapter`：值得长期回看的结构事实或人生故事。

不再维护 Story Thread / Stage 1 / Stage 2 / Stage 3。

---

## “最近”是效率视图，不是故事阅读区

玩家打开居民面板时，“最近”的第一目标是快速了解：

> 这个人这几天都在干什么。

因此每一项都只显示：

~~~text
时间 + 一句短文本
~~~

例如：

~~~text
2日前  去朋友家坐了一阵。
4日前  有人来给家里说亲。
7日前  去市上买了些粮。
11日前 帮邻居修好了院门。
~~~

禁止在“最近”里显示：

- 标题 + 长正文；
- 多段故事；
- memoryText；
- 来源标签；
- Action / LifeEvent 技术标签；
- Story / Stage 系统结构；
- “故事卡”式阅读体验。

即使是成婚、服役、迁居等重要事件，近期也只显示一句：

~~~text
3日前  和城南张家姑娘成了婚。
~~~

而不是在居民面板里展开完整故事。

---

## RecentAction 与 RecentLifeEvent

数据层仍然可以区分：

~~~text
RecentAction
RecentLifeEvent
~~~

但展示层统一成同样的短句密度，按时间从近到远排序。

### RecentAction

来自真实 Behaviour 完成。

例如：

~~~text
去井边挑了水回来。
去朋友家坐了一阵。
收工后在街上走了走。
~~~

丰富度应该来自真实 Behaviour 种类，不为“最近”单独发明模拟算法。

### RecentLifeEvent

用于普通 Behaviour 无法直接表达的近期事实，例如：

~~~text
有人来给家里说亲。
孩子第一天进了私塾。
旧同伍进城来看我。
今日成了婚。
~~~

RecentLifeEvent 仍然不是长故事。

它只提供一条适合快速扫描的 `recentText` / Presentation。

---

## LifeEvent 与人生故事

LifeEvent 是一次完整发生的离散事件，但它的两个玩家展示面必须分开：

~~~text
LifeEvent
├─ recentText
│  └─ 最近：一句短记录
└─ memoryText?
   └─ 人生经历：完整回忆
~~~

不是所有 LifeEvent 都需要 memoryText。

普通事件：

~~~text
发生
→ recentText
→ 最近
→ 自然淘汰
~~~

重要事件：

~~~text
结构事实 / Tag / 年龄 / 职业等
→ LifeEvent 获得资格并发生
→ recentText 进入最近
→ 写入 LifeChapter
→ memoryText 长期保留在人生经历
~~~

---

## LifeChapter 才是故事阅读区

人生经历是一条年龄升序时间轴。

### Fact Chapter

结构事实本身已经足够：

- 开始一份营生；
- 成婚；
- 添孩子；
- 搬家；
- 换工作。

通常只显示：

~~~text
年龄 + 标题
~~~

### Story Chapter

真正值得玩家认识这个人的人生故事：

~~~text
年龄 + 标题
→ 点击展开
→ memoryText
~~~

`memoryText` 才允许较长的第一人称叙事。

推荐约 80～180 个中文字符，保留具体人物、动作、地点或物件。

---

## Tag / 结构事实决定故事资格

人生经历不是打开 UI 时根据当前 Tag 临时拼出来的。

正确链路是：

~~~text
真实结构事实
+
长期 LifeTag
+
少量短期机会 Tag
+
年龄 / 职业 / 家庭 / 世界条件
        ↓
决定哪些 LifeEvent / Story Chapter 候选有资格发生
        ↓
某个事件真正发生
        ↓
写入 LifeChapter
        ↓
以后打开人生经历时读取已经发生的 Chapter
~~~

因此：

> Tag 决定故事“能不能发生”，不是用来每次打开面板重新解释过去。

已经发生的过去不会因为以后资源库增加、Tag 变化或候选权重变化而被重新生成。

---

## 结构事实优先于 Tag

连续性判断优先级：

~~~text
真实结构状态
>
长期 LifeTag
>
短期机会 Tag
~~~

能从结构状态直接知道的事实，不重复存 Tag。

不要创建：

~~~text
lifetag.married
lifetag.has-child
lifetag.is-carpenter
~~~

长期 Tag 用于记录当前结构已经看不出来的过去，例如：

~~~text
lifetag.served-military
lifetag.first-independent-task
lifetag.opened-shop
lifetag.migrated
~~~

短期 Tag 只负责短时间内增加后续故事机会，例如：

~~~text
lifetag.newly-married
lifetag.courtship-open
lifetag.betrothed
~~~

禁止把 Tag 重新做成：

~~~text
story-x-stage-1
story-x-stage-2
story-x-stage-3
~~~

---

## CurrentAction 与故事分离

`CurrentAction` 只来自真实 Behaviour。

一个居民最近刚刚：

~~~text
有人来给家里说亲。
~~~

此刻仍然可以：

~~~text
正在木作铺做工。
~~~

如果某个事件应真正改变行为，例如服役、求医或旅行，由 Unity 的 Schedule / Utility / Story Action Request 改变 Behaviour；UI 不伪造 CurrentAction。

---

## 内容生产分成两条线

### Recent 内容线

目标：提高玩家快速了解居民生活的效率与丰富度。

主要生产：

- Action Presentation Variant；
- LifeEvent `recentText`；
- 必要的短期事实展示。

规则：

- 一句话；
- 短；
- 可扫读；
- 不讲完整故事；
- 不重复 Behaviour 已经能表达的内容。

### Life History 内容线

目标：提高居民的人生差异和故事感。

主要生产：

- Fact Chapter 语义；
- recordable LifeEvent；
- memoryText；
- Tag / 结构事实驱动的后续故事候选。

规则：

- 低频；
- 稀疏；
- 允许多年没有重大故事；
- 由事实 / Tag 提供连续性；
- 不为了填满时间轴制造大事。
