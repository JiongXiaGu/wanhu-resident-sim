# 居民生活记录与故事连续性

## 目标

居民系统只保留三个玩家时间尺度：

~~~text
此刻
最近
人生经历
~~~

分别回答：

~~~text
此刻       这个人现在真的在做什么
最近       这个人最近真实做过或遇到过什么
人生经历   这个人一生中哪些事情值得长期记住
~~~

数据来源保持分层，但 UI 不把内部系统分类强加给玩家。

---

## 三层关系

~~~text
Resident
├─ CurrentAction
├─ Recent
│  ├─ RecentAction
│  └─ recent LifeEvent
└─ LifeChapter
~~~

- `CurrentAction`：真实 Behaviour 当前状态。
- `RecentAction`：真实 Behaviour 完成后的近期记录。
- `LifeEvent`：一次完整发生的离散生活事件。
- `LifeChapter`：值得长期回看的重要事实或事件。

不再维护“当前 Story Thread / Stage 1 / Stage 2 / Stage 3”作为长期内容模型。

---

## LifeEvent 是一次完整事件

LifeEvent 的基本单位是：

> 一次已经足够独立、可以单独讲清楚的事情。

例如：

- 邻居来借了一次手；
- 有人来给家里说亲；
- 这门亲事谈妥了；
- 成婚；
- 家里添了孩子；
- 第一次独自替家里办事；
- 被征去服役；
- 服役结束回家；
- 旧同伍进城；
- 孩子开始入学；
- 晚年开始常去街口下棋。

一个 LifeEvent 不再被强制拆成三个阶段。

如果一件事情确实跨越很长时间并存在多个有意义的节点，应把这些节点写成多个独立 LifeEvent，再用真实结构事实或少量 LifeTag 产生连续性。

---

## 连续故事由事实与 Tag 串联

推荐：

~~~text
LifeEvent A
→ 改变结构事实 / 写入 Tag
→ 一段时间后

LifeEvent B
eligibility 读取结构事实 / Tag
→ 再产生结果
→ 一段时间后

LifeEvent C
~~~

例如婚嫁：

~~~text
有人来说亲
→ 临时机会：marriage-discussing

两边谈妥
→ 移除 marriage-discussing
→ 临时机会：marriage-engaged

成婚
→ 真正建立 spouse / Household
→ 临时机会：newly-married

两个人一起过日子以后
→ require spouse + newly-married
→ 消费 newly-married
~~~

具体 ID 在 LifeEvent V3 数据迁移时统一确定；文档不提前要求 Unity 使用某种事件状态机。

---

## 结构事实优先于 Tag

连续性判断优先级：

~~~text
真实结构状态
>
长期 LifeTag
>
短期机会 Tag
~~~

### 真实结构状态

能直接从居民 / 家庭状态知道的事实，不重复写 Tag。

例如：

- 是否有配偶 → spouse / Household；
- 是否有孩子 → childCount / child relation；
- 当前职业 → occupation；
- 当前住处 → Household / home；
- 当前是否服役 → 若 Unity 本身有对应状态，则读真实状态。

不要额外保存：

~~~text
lifetag.married
lifetag.has-child
lifetag.is-carpenter
~~~

这类重复状态。

### 长期 LifeTag

用于记录“当前结构状态已经看不出来，但过去发生过这件事”。

例如：

~~~text
lifetag.served-military
lifetag.first-independent-task
lifetag.child-started-school
~~~

它们可以在多年后解锁新的 LifeEvent。

### 短期机会 Tag

只为后续一小段人生提供候选机会。

例如：

~~~text
lifetag.newly-married
lifetag.marriage-discussing
~~~

后续事件消费后应移除。

禁止把 Tag 写成新的 Stage 系统：

~~~text
story-x-stage-1
story-x-stage-2
story-x-stage-3
~~~

---

## “最近”统一展示行为与事件

数据层继续区分：

~~~text
RecentAction
LifeEvent
~~~

但玩家当前生活页只看到一个：

~~~text
最近
~~~

展示层按时间混合排序。

例如：

~~~text
2日前  去朋友家坐了一阵
4日前  有人来给家里说亲
7日前  去市上买了粮
11日前 邻居为了院墙的事来商量
~~~

不要再分别显示：

~~~text
正在经历
最近发生
最近
~~~

也不要在 UI 中显示“Action / LifeEvent”技术标签。

RecentAction 可以只显示一句行为文本；LifeEvent 可以显示标题和一段短正文。具体视觉密度由 Resident Panel V3 约束。

---

## LifeChapter

人生经历仍是一条年龄升序时间轴。

LifeChapter 分两类。

### Fact Chapter

结构事实本身已经足够说明意义：

- 开始一份营生；
- 成婚；
- 添孩子；
- 搬家；
- 换工作。

通常只显示：

~~~text
年龄 + 标题
~~~

不为了文学感强行写故事正文。

### Story Chapter

重要 LifeEvent 可以：

~~~text
recordToHistory = true
memoryText = 第一人称完整回忆
~~~

在人生页默认收起，玩家主动展开才看 memoryText。

如果一个 LifeEvent 同时造成结构事实，而且二者表达的是同一件事，人生时间轴只保留一个节点，不重复出现“成婚”和“这门亲事定下来了”两个同义 Chapter。

---

## 哪些事情进入人生经历

进入 LifeChapter 的标准是：

> 多年以后，玩家回看这个居民时，这件事仍然值得知道。

通常包括：

- 成婚；
- 添孩子；
- 换职业；
- 搬家；
- 服役；
- 第一次承担重要责任；
- 孩子入学；
- 长期疾病或重大恢复；
- 晚年形成新的生活方式；
- 对人生方向有明显影响的合作、损失或变化。

通常不包括：

- 一次普通买粮；
- 一次散步；
- 一次小雨耽误做活；
- 一次普通串门；
- 很快恢复原状的小纠纷。

人生经历允许稀疏，不给每个年龄阶段强行填故事。

---

## CurrentAction 与 LifeEvent 分离

`CurrentAction` 只来自真实 Behaviour。

LifeEvent 不占用“此刻”栏，也不覆盖 CurrentAction。

例如居民刚刚经历：

~~~text
有人来给家里说亲
~~~

此刻仍可以真实地：

~~~text
正在木作铺做工
~~~

如果某个 LifeEvent 应真正改变行为，例如服役、求医或旅行，由 Unity 的 Schedule / Utility / Story Action Request 改变 Behaviour；UI 不伪造行为。

---

## 内容生产原则

新的 LifeEvent 内容优先满足：

- 一次事件能独立读懂；
- 第一人称；
- 具体动作和生活细节；
- 不依赖固定三幕节奏；
- 不为了“连续”强行写后续；
- 后续关系通过事实 / Tag 自然产生；
- 同一 Tag 可以允许多个不同后续，而不是锁定唯一下一集；
- 普通事件与重要人生事件比例自然；
- 不把居民都写成连续遭遇大事的剧情主角。

## 当前迁移边界

当前 main 的实现仍是 `wanhu.life-events.v2`，Schema 仍要求 `stages[3]`，Resident Panel 仍有独立 LifeEvent 区域。

从本规则生效后：

1. 不再新增三阶段 LifeEvent V2 内容；
2. 不继续扩 Story Thread / Stage 运行逻辑；
3. 下一代码批次统一迁移到 LifeEvent V3；
4. 迁移时不保留 V2 双轨兼容，旧方案需要时从 Git 历史获取；
5. V3 迁移完成后再正式开始 LifeEvent 内容扩充。

现有 14 条 LifeEvent 只作为迁移输入，不是新内容模板。
