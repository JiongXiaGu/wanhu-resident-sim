# 居民个人资料与头像派生 V1

## 目的

居民需要先是一个稳定的人，再拥有当前职业、家庭和外观。个人资料用于居民面板、后续 Utility / 故事 Eligibility 的弱输入，以及默认头像的稳定偏好。玩家手动编辑头像后立即让位。

## Resident Profile V1

每个居民生成三项稳定资料：temperamentId、lifeFocusId、presentationStyleId。

性情候选：沉稳、活络、内敛、热络、细致、果断。性情不用于决定脸型。

生活侧重候选：顾家、重手艺、爱钻研、重生计、重人情、爱走动。它由稳定 seed 与职业组权重共同生成。

穿戴倾向候选：利落、整洁、讲究。它由稳定 seed、家庭财富和职业组共同生成，只表达偏好，不是阶层锁定。

资料源：Content/Residents/resident-profile-catalog.json。构建时由 ResidentProfileCompiler 写入最终 Resident Snapshot。

## 默认头像派生

居民没有玩家覆盖时，ResidentAvatar 使用 chibi-cute-v1 的真实 Catalog 自动生成四项 Recipe。

输入：Resident seed、Gender、LifeStage、OccupationGroup、Household Wealth、Resident Profile。

规则：

1. Face 只由稳定居民 seed 在当前 Frame 的可用 Face 中选择；职业、财富、性情不改脸。
2. Hair / Outfit 由职业组得到弱主题倾向：手工业/农事/城建水利偏 labor，商贸/演艺偏 merchant，运输偏 traveler，医护/学业/退养/儿童偏 common。
3. lifeFocus 只在 common 居民中小概率偏向 labor / merchant / traveler；非 common 职业也有少量概率穿普通常服，避免同职业像制服复制。
4. presentationStyleId 与财富进入稳定选择 salt，让同职业、同年龄仍有差异。
5. 活络/热络默认微笑，其余默认平静。
6. Frame 没有对应主题时回到 common / 当前 Frame 可用项。

优先级：玩家已保存 Avatar Recipe > 个人资料派生默认 chibi Recipe > 冻结 Portrait fallback。

“恢复原头像”回到个人资料派生默认；正式 PortraitRenderer 仍保留为独立 fallback 契约和审查页。

## UI

Resident Panel Hero 在地区/家庭下面显示三项轻量标签，例如：沉稳 · 重手艺 · 利落。它们不是 Buff，也不显示数值条。
