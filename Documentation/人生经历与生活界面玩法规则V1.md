# 人生经历与生活界面玩法规则 V1

## 目标

Web Demo 只验证玩法与内容体验。当前重点是把“现在的生活”和“过去的人生”做成两种明确不同的阅读体验；不在这里设计 Unity Save、Blob、ECS Runtime 布局。

## 生活模式

生活模式回答：**这个人现在过得怎么样？**

只展示：

- `此刻`：真实 CurrentAction。
- `正在经历 / 最近发生`：当前 LifeEvent，按三个阶段随时间推进。
- `最近`：少量 RecentAction。

LifeEvent 完成后可以短暂留在“最近发生”，随后从生活模式淡出。普通 RecentAction 不进入人生经历。

## 人生经历模式

人生经历回答：**这个人过去经历过什么，怎么走到今天？**

规则：

1. 只有一条纵向时间轴，不再使用“童年 / 少年 / 青年 / 壮年 / 中年 / 晚年”等分组。
2. 所有节点按年龄从小到大排列，玩家从上往下阅读一个人的一生。
3. 一个节点只代表一件人生事件；一个故事只形成一个节点。
4. 普通事实节点只显示 `年龄 + 标题`，不显示“人生节点”等系统标签。
5. 故事节点默认收起；玩家点开时，只展开这一件往事。
6. 历史页不再展示 `起初 / 后来 / 最后`、Stage 编号、来源标签等事件系统结构。
7. 时间轴末尾保留 `如今`，连接过去与当前生活。

## Stage Text 与 Memory Text

LifeEvent 有两种不同用途的正文：

### `stages`

服务生活模式。描述事情正在发生时玩家逐步看到的过程。

### `memoryText`

服务人生经历。事情结束并沉淀后，以居民第一人称回忆的方式，压缩成一段完整往事。

`memoryText` 不是把三个 Stage 原文机械拼接，也不带“起初 / 后来 / 最后”等系统化标签。它应该读起来像居民多年后回想：

> 我开始问附近哪家私塾合适。孩子那阵子总爱盯着牌匾上的字，我和家里商量，想着该让他正经认字了。送到门口时他还一直回头看，先生领进去以后，我反倒在门外站了一会儿才走。后来有一天回家路上，他忽然把一家铺子的招牌念了出来，虽然只认得几个字，也够他高兴一路。

## 哪些事件需要 Memory Text

只要事件会成为长期 Life Chapter，就必须有 `memoryText`：

- `recordToHistory: true`；或
- 带会形成长期人生变化的结构型 Effect，例如成婚。

普通天气、邻里小事、短期忙碌等不需要为了历史页额外写 `memoryText`。

## Web 验收重点

玩家体验时主要判断：

- 从最年轻的节点一路往下读，是否像在看这个人的一生；
- 每个节点是否只讲一件事；
- 展开后的文字是否像角色自己的回忆，而不是事件系统记录；
- 生活模式与人生模式是否各自清楚，不互相重复；
- 重要故事是否值得被长期记住，普通琐事是否会自然淡出。
